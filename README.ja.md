# kisui-terminal

[English](README.md)

kisui-terminal は、[shijimi-editor](https://github.com/mm1995tk/shijimi-editor) と強く連携する、ターミナル中心の作業環境です。窓をペインに分け、ペインにターミナル（その中で `shj`）・動画・画像・PDF・ファイルツリーを置きます。名前の汽水は、しじみがすむ場所です。

shijimi-editor とは別のアプリで、版もリリースも別です。組み合わせを確かめた版の `shj` を同梱し、ペインの中のターミナルでは同梱の `shj` を先に使います（自分で入れた `shj` は、kisui-terminal の外では今まで通り使われます）。kisui-terminal と `shj` のやりとりの取り決めは [docs/protocol.md](docs/protocol.md) にあり、コードは共有しません。

## 入れ方

Linux（x86_64 と aarch64）と、Apple シリコン（arm64）の macOS で動きます。Intel の macOS には、アプリとしても ssh 先としても対応しません。版は [Releases](https://github.com/mm1995tk/kisui-terminal/releases) にあります。AppImage と `.dmg` は自動で更新されます。

- **AppImage**：`chmod +x kisui-terminal-linux-*.AppImage` してから起動します。AppImage は 2 週間に 1 回、最新の版に足すので、新しい版にはしばらく `.dmg` だけのことがあります。
- **`.dmg`**：Apple の署名が無いので、macOS は初回に開くのを断ります。`kisui-terminal.app` をアプリケーションに入れて 1 度開き（「確認できません」と出たら閉じます）、**システム設定 → プライバシーとセキュリティ** で `kisui-terminal` についての表示の横にある **このまま開く** を押します。次からは普通に開けます。代わりに `xattr -dr com.apple.quarantine /Applications/kisui-terminal.app` を 1 度だけ実行してもかまいません。アプリは ad-hoc 署名だけなので、更新するたびに、プライバシーとセキュリティで入れた許可（**アプリ管理** など）を入れ直す必要があります。

main の nightly 版は `kisui-terminal-nightly` で、[`nightly` の pre-release](https://github.com/mm1995tk/kisui-terminal/releases/tag/nightly) に置いています（`.dmg` だけです。Linux で nightly 版を使うなら Nix で入れます）。名前と identifier が違うので、普通の版と並べて入れられます。

Nix では、パッケージ `kisui-terminal`（nightly 版は `kisui-terminal-nightly`。同じ名前で入ります）か、home-manager で flake の `homeManagerModules.default` を import して `programs.kisui-terminal.enable = true;` で入れます。Nix で入れた版に自動更新はありません。`nix flake update` で進めます。アプリは別の方法で入れ（macOS の .dmg など）、設定だけを home-manager で置くときは、`programs.kisui-terminal.package = null;` と書きます（パッケージを入れません）。設定を置くフォルダは `programs.kisui-terminal.channel` で選びます（`"stable"` なら `~/.config/kisui-terminal/`、`"nightly"` なら `~/.config/kisui-terminal-nightly/`。書かなければ、パッケージがあるときはパッケージの名前で、`package = null` のときは `"stable"` で決まります。パッケージと食い違う `channel` は、評価の時点でエラーになります）。例: `programs.kisui-terminal = { enable = true; package = null; channel = "nightly"; settings = { /* ... */ }; };`

```sh
nix run github:mm1995tk/kisui-terminal
nix profile install github:mm1995tk/kisui-terminal
nix profile install github:mm1995tk/kisui-terminal#kisui-terminal-nightly
```

## 使い方

kisui-terminal の中での `shj` の動き（開くペイン、動画、URL の開き方、ファイルツリー）は shijimi-editor のマニュアルにあります。[ターミナル](https://mm1995tk.github.io/shijimi-editor/manual/ja/terminal/)・[ブラウザ](https://mm1995tk.github.io/shijimi-editor/manual/ja/browser/)・[設定ファイル](https://mm1995tk.github.io/shijimi-editor/manual/ja/config/)を見てください。

ペインの中で `kisui open <ファイル|URL>` を打つと、画像は打ったペインのカーソルの位置にそのまま出ます（kitty の `icat` と同じ。kitty の画像のプロトコルで端末に書き出すので、ssh 先のマシンのペインでも出ます。PNG・JPEG・GIF（最初のコマ）・WebP・BMP で、ペインの幅までの大きさ）。ほかのファイルは、種類に合うペインに、同じワークスペースの中で開きます。動画・PDF（拡張子で見分け、拡張子で分からなければファイルの頭の中身で見分ける）です。同じ種類のペインが開いていれば入れ替えます。`kisui open --pane <画像>` なら、画像も別のペインに開きます。SVG・AVIF の画像、16 MB か 10000 ピクセルを超える画像、標準出力が端末でないとき（パイプ、コーディングエージェントのシェル）の画像は、`--pane` が無くてもペインに開きます。`http`・`https` の URL はペインにせず、kisui-terminal が動いている手元のブラウザで開きます。内蔵ブラウザを使っていれば（下の `[gui.browser]`）ワークスペースの新しいタブで、使っていなければ OS 既定のブラウザで開きます。`shj` が開くよう頼んだ URL も同じです。ssh 先のマシンの `localhost` の URL は、kisui-terminal が普通の ssh のセッションの上で張る中継（ssh 先の `kisui relay`）越しに開くので、ssh 先のページが見えます（ssh のポート転送は使わないので、ポート転送を断る環境でも開けます）。ssh 先のマシンのペインでも使えます。使えるのは kisui-terminal のペインの中だけで、ほかのシェルから打つと断ります。コマンドの一覧は `kisui --help` で出ます。

```sh
kisui open ./diagram.png         # このペインに出す
kisui open --pane ./diagram.png  # 別のペインに出す
kisui open ./talk.mp4
kisui open ./paper.pdf
kisui open https://example.com/
```

`kisui notify <文>` は、窓の動いているコンピュータ（手元）にデスクトップ通知を出します。長いコマンドの終わりを知るのに使えます。`kisui clipboard copy` は標準入力の文を手元のクリップボードに入れ、`kisui clipboard paste` は手元のクリップボードの文を標準出力に出します。手元のクリップボードを読まれるのは危ないので、`paste` のたびに kisui-terminal が許すかを聞き、許したときだけ出します。3 つとも ssh 先のマシンのペインでも同じように使えます。

```sh
make build; kisui notify "build: $?"
echo hello | kisui clipboard copy
kisui clipboard paste > note.txt
```

ペインのシェルでは、`pbcopy` と `pbpaste` もそれぞれ `kisui clipboard copy` と `kisui clipboard paste` を呼びます（`echo hello | pbcopy`）。`pbpaste` も読むたびに許すかを聞きます。ssh 先のマシンのペインでも同じです。kisui-terminal は zsh・bash・fish の起動ファイルを読んだあとに、この 2 つを置いたフォルダを `PATH` の先頭に入れるので、macOS の `pbcopy` より先になり、スクリプトの中から呼んでも同じに動きます。ユーザーの起動ファイルは書き換えません。ほかのシェルでは `PATH` の先頭に足すだけなので、起動ファイルが `PATH` を組み直すと macOS の `pbcopy` が先になることがあります。

kisui-terminal は、手元のクリップボードにコピーした文の履歴を持ちます。kisui-terminal の中のコピーも、ほかのアプリ（ブラウザなど）でのコピーも入ります。新しい 20 件を 12 時間残し、データのディレクトリ（macOS は `~/Library/Application Support/dev.mm1995tk.kisui-terminal`、Linux は `~/.local/share/dev.mm1995tk.kisui-terminal`）の `clipboard-history.json`（自分だけが読めるファイル）に保存するので、閉じても消えません。パスワード管理アプリが「秘密」の印を付けたコピーと、画像は入れません。

`Cmd+Shift+H`（macOS）か `Ctrl+Shift+H`（Linux）で、履歴を新しい順の一覧で開きます。文字を打つと絞り込め、上下キー（か `Ctrl+J` / `Ctrl+K`）で選び、`Enter` で打っていたペインに貼り、`Shift+Enter` でクリップボードに戻します。`Esc` は何もせずに閉じます。

kisui-terminal の外（ほかのアプリを使っているとき）でも、`Option+Space`（macOS）か `Alt+Space`（Linux）で、履歴の小さな窓が前に出ます。kisui-terminal のメインの窓は前に出ません。上下キー（か `Ctrl+J` / `Ctrl+K`）で選んで `Enter` を押すと、その文をクリップボードに戻し、「コピーしました」を少し出してから窓を閉じて前に使っていたアプリに戻るので、`Cmd+V`（Linux は `Ctrl+V`）で貼ります。kisui-terminal からは貼る操作を送らないので、macOS のアクセシビリティの許可は要りません。`Esc` は何もせずに閉じて前のアプリに戻ります。使えるのは kisui-terminal が起動している間だけです。Linux では、`Alt+Space` をウィンドウマネージャー（GNOME や KDE の窓のメニューなど）が先に取っていると届きません。そのときは、ウィンドウマネージャーの側でそのキーを外してください。Wayland のセッションでは全体のキーを取れないことがあります（X11 のアプリを使っている間だけ届くことがあります）。

`kisui pane split --right` / `--down` / `--left` / `--up` は、打ったペインを右・下・左・上に分け、新しいペインにフォーカスを移します。後ろにコマンドを付けると、新しいペインではシェルの代わりにそのコマンドを動かします（`kisui pane split --down htop`）。コマンドが終わるとペインも閉じるので、短いコマンドの出力を残したいときは、シェルに動かさせて最後にシェルを残します（`kisui pane split --down sh -c "ls; exec sh"`）。分けた後のペインが 20 列（`--right`・`--left`）・5 行（`--down`・`--up`）より小さくなるときは、キーで分けるときと同じく断ります。`kisui pane title <名前>` は、ペインの上の細い帯に名前を出します（空の名前なら外します）。名前は serve が持つので、ウィンドウを開き直しても残ります。名前は 1 つのマシン（1 つの `kisui serve`）の中で重なりません。どのワークスペース・タブのものでも、ほかのペインが使っている名前は断ります。ペインの id の形の名前（`t` と数字。`t3` など）も断ります。`kisui pane split` に `--name <名前>` を付けると、新しいペインにその名前を付けます（`kisui pane split --right --name dev`）。`kisui pane list` は、このマシンの全部のペインを（どのワークスペース・タブのものも）一覧にします。id・名前・タブ・フォルダ（cwd）・プログラムが付けたタイトルを出し、打ったペインに `*` を付けます。`kisui pane list --json` は同じものを、プログラム（やエージェント）が読む JSON で出します。`kisui pane send <名前|id> <文字>` は、名前か id で指したこのマシンのペイン（どのワークスペース・タブのものでも。届くペインの範囲は下を参照）に文字を打ち、Enter を押します。`kisui pane keys <名前|id> <キー>...` はそのペインでキーを押します（`esc`・`ctrl+c`・`up`・`enter` など。`kisui pane keys --help` で一覧を出します）。`kisui pane close <名前|id>` はそのペインを閉じます。どれもフォーカスは移らないので、あるペインのエージェントが、新しいペインで別のエージェントを起動して指示を送れます。ペインのプログラムが bracketed paste を有効にしていれば（多くのシェルとエージェントはしています）、文字は貼り付けとして送るので、何行もの文字が 1 つにまとまって届きます。文字の中の改行は Enter になります。`send` は、相手のプログラムの処理が終わるのを待ちません。タブのプライマリのペインは `kisui pane close` では閉じず、タブといっしょに閉じます。

```sh
kisui pane split --right
kisui pane split --down npm run dev
kisui pane title build
kisui pane split --down --name dev npm run dev
kisui pane list --json
kisui pane send build "make test"
kisui pane keys build ctrl+c
kisui pane close dev
kisui pane open --workspace review --name reviewer -- claude
```

`kisui pane read <名前|id>` は、名前か id で指したこのマシンのペイン（どのワークスペース・タブのものでも。届くペインの範囲は下を参照）の画面の字を出します。あるペインのエージェントが、別のペインのエージェントやコマンドが出しているものを見られます。`--lines <数>` を付けると、画面の上の scrollback もその行数だけ出します（serve が持つ 5000 行まで）。出すのは字だけで、色は付きません。端末が折り返した行は 1 行にして出し、行末の空白と、画面の下の何も無い行は出しません。全画面のプログラム（`shj` や `htop` など）は scrollback の無い画面に描くので、そこでは `--lines` を付けても増えません。プログラムがとても速く大量に出力すると（`yes` のように、serve が追いつけない分が約 4 MB を超えると）、serve は追いつけなかった分を捨てるので、プログラムが画面を描き直すまでは、その後に出た分しか出ません。

`kisui pane open --workspace <ワークスペース> [--new] --name <名前> [--cwd <フォルダ>] [-- コマンド ...]` は、ウィンドウのワークスペース（サイドバーに出ている名前で指します。`review`・`ws2` など）の最後にターミナルのタブを足し、そこでコマンド（無ければシェル）を動かし、タブのペインに名前を付けます。あるペインのエージェントが、別のワークスペースで別のエージェントを起動し、`kisui pane send` と `kisui pane read` で使えます（`kisui pane open --workspace review --name reviewer -- claude`）。`--new` を付けると、その名前のワークスペースを新しく作ります。`--new` が無いときは、その名前のワークスペースが無いか、2 つ以上あれば断ります。`--new` があるときは、その名前のワークスペースがもうあれば断ります。タブは打ったペインのマシンにでき、`--cwd`（書かなければ今のフォルダ）で始まります。フォーカスは移りません。名前は `kisui pane title` と同じ決まりで、ほかのペインが使っていれば、タブを作らずに断ります。コマンドはタブのプライマリのペインで動くので、コマンドが終わってもペインは出力を残したまま残ります（`kisui pane close` では閉じません。タブを閉じます）。コマンド無しで開いたシェルが終わったときは、タブが閉じます。ワークスペースはウィンドウが持つので、ウィンドウが閉じていれば理由を出して失敗します。

```sh
kisui pane read build
kisui pane read t5 --lines 200
```

**これらのコマンドが届くペイン。** `kisui pane send`・`keys`・`read`・`close`・`list` が届くのは、打ったペイン自身と、そのペインが開いたペイン（`kisui pane split` か `kisui pane open` で）と、そのペインがさらに開いたペインです。あなたがウィンドウの操作で開いたペインと、ほかのペインが開いたペインには届きません。あるペインの中のプログラムが、あなたが root になっているペインや、別のマシンにログインしているペインに字を打つことも、その画面を読むこともできません。届かないペインは `kisui pane list` に出ず、指すと、どのペインにも無い名前を指したときと同じ形で失敗します。`--machine` を付けたときも、相手のマシンで同じです。届くのは、このペインがそこに開いたペイン（`kisui pane open --machine`）と、そこから開いたペインです。あるマシンの全部のペインに届くようにするには、そのマシンの設定ファイルの `[server]` に `pane_reach = "all"` と書きます（下の設定を参照）。

`--machine <マシン>` を付けると、`kisui pane list`・`send`・`keys`・`close`・`read`・`open` が別のマシンのペインに効きます。マシンは、`[[gui.machines]]` の名前（名前が無ければ ssh の行き先）で指すか、`local` と書きます。`local` は常に、ウィンドウの動く手元の PC です。手元の PC のペインからは、`--machine` でウィンドウのどのマシンにも届きます（`kisui pane read --machine dev bar`）。ssh 先のマシンのペインから別の ssh 先のマシンに届くのは、手元の PC の設定ファイルでそのマシンに許したときだけです。そのマシンの `[[gui.machines]]` の `allow_pane_to` に、指してよい名前を並べます。手元の PC（`local`）は、設定ファイルでは許せません。ウィンドウで、時間を決めて許します。マシンのダイアログ（リーダー → `m`）でマシンを選んで `p` を押し、時間（`30m`・`1h`・`1h30m`。8 時間まで）を打って `Enter` を押します。`P` で途中で終えられ、ウィンドウを閉じると消えます。許している間、手元の PC にペインを作る頼み（`kisui pane open --machine local`）は、そのたびにウィンドウが聞きます。コマンドの全文・フォルダ・名前・ワークスペースを見せ、最初に選ばれているのは `Deny` です。許すときは、そのペインを任せる（以後聞かない）か、そのペイン（と、そこから開いたペイン）への `send`・`keys`・`read`・`close` も毎回聞くかを選びます。コマンドは、あなたの答えを 90 秒まで待ちます。許していないマシンは、ほかのどのマシンにも届かず、コマンドは許し方を出して失敗します。マシンの serve は自分のペインしか知らないので、全部のマシンにつながっているウィンドウが頼みを中継します。ウィンドウが閉じているときや、そのマシンにつながっていないときは、理由を出して失敗します。`kisui pane open --machine` のタブは、そのマシンのターミナルです。`--cwd` とコマンドは、そのマシンの絶対パスで書きます（`--cwd` が無ければ、そのマシンの始めのフォルダで始まります）。または、シェルを開いて `kisui pane send` でコマンドを始めます。上に書いた、ssh 先のマシンから手元の PC への頼みのほかは、kisui-terminal は確認を出しません。どこで何をするかは全部コマンドの引数に出ているので、それを動かすエージェントの権限の決まりで判断できます。名前が `local` のマシン（`[[gui.machines]]` のものか、この版より前にウィンドウで足したもの）は `--machine` で選べず、別の名前を付けるようお知らせが出ます。

```sh
kisui pane list --machine dev
kisui pane open --machine dev --workspace review --name reviewer --cwd /home/me/repo
kisui pane send --machine dev reviewer claude
kisui pane read --machine dev reviewer
```

`kisui db` は、ペインの中のコーディングエージェントが、設定の DB の接続（`[[db.connections]]`。下）を使うためのコマンドです。`kisui db connections` は接続の一覧と、それぞれでエージェントがしてよいことを出します。`kisui db schema <接続> [<テーブル>]` はテーブルの一覧か、テーブル 1 つの列を出します。`kisui db query <接続> <SQL>` は文を 1 つ実行して行を出します。`kisui db propose <接続> <SQL>` は、DB のタブの入力欄に SQL を書きます（読んで実行するのはあなたです）。`--variant <変種>` で変種のある接続の環境を選び、`--json` でプログラム向けの結果を出します。DB につないでログインするのは、ペインのマシンの `kisui serve` なので、エージェントはクライアントを要らず、パスワードも見ません。どの頼みもエージェントのものとして扱い、エージェントに付けた権限（`agent-permission`）に従います：権限を書いていなければ、`kisui db query` は断られ、`kisui db propose` は許されます。`run = "read"` なら、書き込みは DB が断ります。`kisui db propose` は何も実行しません。タブの入力欄に SQL があるときは、上書きの前に窓が聞きます（`Enter` で上書き、`Esc` でやめる。やめるとコマンドは失敗します）。コマンドはパスワードを聞きません：キーチェーンか `~/.pgpass`・`~/.my.cnf` に置きます（DB のタブで入力済みなら、その窓を開いている間は、それも使われます）。エージェントが実行した文は、その接続の SQL の履歴に「エージェント」の札を付けて残ります。詳しくは [docs/database.md](docs/database.md#for-a-coding-agent-the-kisui-db-commands)。

```sh
kisui db connections
kisui db schema --variant prod shop orders
kisui db query --variant prod shop 'SELECT count(*) FROM orders'
kisui db propose --variant prod shop "UPDATE orders SET status = 'cancelled' WHERE id = 42"
```

`kisui update` は、アプリに新しい版を今すぐ調べ直させます。アプリを閉じて開き直さなくてすみます（何もしなければ、調べるのは起動したときの 1 回だけです）。新しい版があれば、起動したときと同じ「新しい版があります」の知らせを出します（「あとで」で閉じていても、出し直します）。「更新して再起動」の動きは、その知らせと同じで、ペインのシェルは残ります（serve が引き継ぎます）。`kisui update` は、アプリが見つけたことを出します。新しい版がある、最新である、この版は自動更新を持たない（Nix で入れた版と、AppImage でない Linux。`nix flake update` で更新するか、新しい版を入れ直す）のどれかです。ssh 先のマシンのペインでも使えます。調べて知らせを出すのは手元のアプリです。使い方は `kisui update --help` で出ます。

`kisui skill install [フォルダ]` は、Claude Code などのコーディングエージェントに、ペインの中での `kisui open`・`kisui notify`・`kisui clipboard`・`kisui pane`・`kisui db` の使い方を教える skill（`SKILL.md`）を書き出します。フォルダを省くと `~/.claude/skills/kisui-terminal/` に書きます。skill は `kisui` のバイナリに入っているので、入れた版に合った内容になります。`kisui clipboard paste` は勝手に呼ばないよう、skill に書いてあります。

```sh

```

kisui-terminal の設定は、kisui-terminal 自身の設定のフォルダの `config.toml` と `config.local.toml` に書きます。フォルダは `~/.config/kisui-terminal/`（nightly 版は、あれば `kisui-terminal-nightly/`。`$XDG_CONFIG_HOME` が絶対パスならそちらを使います）。`config.toml` を土台に、`config.local.toml` を上に重ねて読みます。同じ項目は `config.local.toml` が勝ちます。`[server]` のような表は項目ごとに重ねます。`[[gui.machines]]` と `[[db.connections]]` の一覧は、1 件ごとに重ねます。マシンは ssh の行き先（`ssh`）、DB の接続は名前（`name`）で見分けます。両方のファイルにある 1 件は、`config.local.toml` のものに丸ごと代わります（`config.toml` の側にだけ書いたキーは引き継ぎません）。片方にしかない 1 件は、どちらも残ります。並びは `config.toml` の順で、そのあとに `config.local.toml` にだけあるものが続きます。そのため、`config.local.toml` にマシンを足しても、`config.toml` のマシンは残ります。`config.local.toml` の空の一覧（`[gui]` の `machines = []`）は、何も足さず、何も消しません。`config.toml` の 1 件を `config.local.toml` から消す書き方はありません（`config.toml` から消します）。どちらのファイルも無くてかまいません。読むのはこの 2 つだけで、`config.nix` は読みません。kisui-terminal 自身が設定を書くときは `config.local.toml` に書き、`config.toml` には書きません。`shj` の設定（`~/.config/shijimi-editor/`）は読みません（`ui-language` も）。home-manager では、この flake のモジュールの `programs.kisui-terminal.settings` に書くと、`config.toml` を作ります。

- `[[gui.machines]]`：マシン（マシンのダイアログ `m` に出て、ワークスペースは切り替えの窓（`w`）に並ぶ。`ssh = "dev-vm"`、`name = "dev"`）。名前は `kisui pane --machine` で指す名前でもある。`local` は、ウィンドウの動く手元の PC を指す予約語。ウィンドウ（マシンのダイアログ `m`）でマシンを足す・名前を変える・外すと、`config.local.toml` の `[[gui.machines]]` に書くので、ウィンドウで足したマシンも dotfiles のマシンも同じ場所で扱える。前の版がウィンドウの中の記録に置いていたマシンは、この版を初めて起動したときに `config.local.toml` に移す。
  - `start_dir` と `shell`：そのマシンの新しいターミナルが始まるフォルダと、そのシェル（`start_dir = "~/work"`、`shell = "/usr/bin/fish"`）。リモートのマシンの設定ファイルは触らず、手元の設定だけで決める。どちらも、そのマシンでのパスを書く：絶対パスか、`~` で始まるパス（`~` は、そのマシンのホーム）。`shell` はシェルのファイルのパスだけで、引数は書けない（`bash` のような名前だけも書けない。`PATH` からは探さない）。リモートのパスは手元で確かめられないので、設定を読むときに確かめるのは形だけで、有るかはそのマシンの `kisui serve` がターミナルを始めるときに確かめる：`start_dir` のフォルダが無ければ、そのマシン自身の設定（下の `[server] start_dir`、無ければホーム）で始める。`shell` が実行できるファイルでなければ、別のシェルに替えずに、理由を出してターミナルを作らない（「ローカル」の `[server] shell` は別：下）。書いていなければ、今までどおり（そのマシンの `[server] start_dir` と `[server] shell`、無ければホームと `$SHELL`）。フォルダを明示したとき（今のタブのフォルダを引き継ぐタブの作成、`kisui pane open --cwd`）は、そのフォルダが勝つ。設定を変えると、`kisui serve` を止めずに、次に作るターミナルから効く（ウィンドウは、ターミナルを作るたびに設定を読み直す）。設定したシェルで始めたターミナルでは、環境変数 `SHELL` もそのシェルになる。ウィンドウでは、マシンのダイアログ（`m`）の `t` で入れる。そのマシンの `kisui serve` が古い（この機能より前の版）間は、何も渡さない（今までどおりに始まる）。
  - `allow_pane_to`（マシンの名前の一覧。例：`allow_pane_to = ["build"]`）：このマシンのペインが `kisui pane --machine` で届いてよい、リモートのマシン。省くと、このマシンからはほかのどのマシンにも届かない。向きごとに別に書く（`dev` から `build` を許しても、`build` から `dev` は許されない）。届いてよいマシンは、相手のマシンでコマンドを動かせるので、そこまで信頼できるマシンにだけ書く。`local`（手元の PC）は、ここに書いても効かず、書いてあるとウィンドウがお知らせを出す。ファイルに書いた許可は、書いたことを忘れても効き続けるので、手元の PC のペインの操作は、ウィンドウで時間を決めて許す（マシンのダイアログの `p`。上の `--machine` を参照）。ウィンドウはこのキーを書かない：ウィンドウで足したマシンは、その項目に手で `allow_pane_to` を書くまで、ほかのどのマシンにも届かない。ウィンドウで名前を変えても、書いた `allow_pane_to` は残る。同じマシンが両方のファイルにあるときは、`config.local.toml` の項目が `config.toml` の項目に丸ごと代わるので、使われるほうの項目に書く。どのマシンの名前でもない語は何も許さず、ウィンドウがお知らせを出す。一覧は、ウィンドウが起動のときに読む。
- `[gui.browser]`：`enabled = true` で内蔵ブラウザを使います（既定は使わない。使わなければ何も変わりません）。ワークスペースごとにブラウザのタブを持てます。タブはサイドバーのワークスペースの下に、ターミナルのタブと一緒に開いた順に並び、タブを選ぶと、ペインの場所すべてがそのタブになります（ワークスペースを選ぶと、そのワークスペースが最後に出していたものが出ます）。名前を付けたタブは、ページの題の代わりにその名前を出します。ページは OS の WebView（macOS は WKWebView、Linux は WebKitGTK）なので、DRM の動画は使えず、パスキーは外のブラウザを通してだけ使えます（下の `passkey_sites`）。リーダーの `a` の窓の `e` で、そのページを OS 既定のブラウザで開けます。ページにキーがあっても、リーダーと近道は効き、ほかのキーはページに届きます。ログイン（Cookie）はすべてのタブで共有し、タブと一緒にディスクに残り、起動し直すと戻ります。タブはデータのディレクトリ（macOS は `~/Library/Application Support/dev.mm1995tk.kisui-terminal`、Linux は `~/.local/share/dev.mm1995tk.kisui-terminal`）の `browser-tabs.json`、ログインは Linux ではそこの `browser/`、macOS では WebView 自身の置き場に残ります。ブックマーク（リーダーの `a` の窓の `b` で足し、`B` で一覧）はすべてのワークスペースで共有し、同じ場所の `browser-bookmarks.json` に残ります。手元の Chrome のブックマーク（`Default` プロファイル。macOS は `~/Library/Application Support/Google/Chrome/Default/Bookmarks`、Linux は `~/.config/google-chrome/Default/Bookmarks`）は読むだけで書かず、新しいタブのページと一覧に、kisui-terminal のものの後ろに（`Chrome` の札を付けて）、Chrome と同じフォルダの入れ子で出します（ブックマークバー・その他のブックマーク・モバイルが根で最初から開き、その下のフォルダは閉じています。フォルダは選んで `Enter`、またはクリックで開け閉めします。絞り込むと、当たったブックマークだけを、入っているフォルダを開いて出します）。ページや一覧を開くたびに読み直し、`Ctrl+D` では消えません。Chrome が無ければ何も出さず、エラーにもしません。ワークスペースを閉じると、その下のタブも閉じます。リーダーの `n` → `B` では、シークレットのタブを開きます。タブだけの、メモリにだけ置くログインを使うので、共有のログインもほかのシークレットのタブのログインも見えず、閉じるとログインは消え、起動し直しても戻りません（サイドバーに「シークレット」の札が付きます）。シークレットのタブでは下の `passkey_sites` は使わず、パスワードと認証アプリのコードでログインできます。ページが新しい窓を開くリンクやスクリプト（`target="_blank"`・`window.open`）は、同じワークスペースの新しいタブで開きます。ログインは開いた元のページと同じで、元のページとのつながり（`window.opener`）も保つので、「GitHub でログイン」などの小窓は元のページに結果を返せます。そのページが自分を閉じると、タブも閉じて元のタブに戻ります。ダウンロードしたファイルは、場所を聞かずにダウンロードのフォルダ（`~/Downloads`）に保存し（同じ名前があれば `名前 (1).拡張子`）、右下のお知らせで知らせます。お知らせから、ファイルを開くこととフォルダを表示することができます（リーダーの `i o` `i f`）。内蔵ブラウザを使っていると、`kisui open <URL>`・`shj` が開くよう頼んだ URL・ターミナルの URL の `cmd + click` は、そのワークスペースの新しいタブで開きます。リモート（ssh）のマシンの `localhost` 系の URL は、下と同じ中継を通してタブで開き、URL の入力欄には中継前の元の URL（`http://localhost:3000/` など）を出します。
- `[gui.browser]` の `passkey_sites`（`enabled = true` のとき）：iCloud キーチェーンや 1Password のパスキーでログインするサイト（`github.com` のような host）を書きます。例：`passkey_sites = ["github.com", "dash.cloudflare.com", ".google.com"]`。host は、完全に同じ host だけに当たります（`github.com` は `gist.github.com` に当たりません）。先頭に `.` を付けた `.google.com` は、`google.com` とそのすべてのサブドメインに当たります。ログインの後に別のサブドメインへ移るサイト（Google は `accounts.google.com` から `myaccount.google.com` に移ります）に使います。公開サフィックス（`.com`・`.co.jp`・`.github.io` のように、誰でもその下にサブドメインを持てる名前）は、他人のサイトの Cookie まで写す対象になるので、この書き方では書けません。書いた項目は使わず、理由をお知らせに出します（ほかの項目は使います）。WebView ではそれらのパスキーを使えないので、書いたサイトのページがパスキーを求めると、kisui-terminal は同じ URL を Firefox で開きます。そこでログインすると、Firefox の kisui-terminal の拡張機能がサイトの Cookie を送り返し、kisui-terminal はそれを内蔵ブラウザに入れて、タブをログインした状態で開き直します。外のブラウザに移るのは一覧に書いたサイトだけで、Cookie を受け取るのも、移ったサイトの分を 10 分以内に 1 回だけです。Firefox でそのサイトにログイン済みのときや、そこでパスワードでログインしたときも、タブが kisui-terminal の開いたページから、そのサイトのログインの途中らしくないページ（ログイン・2 段階認証・確認のページでないもの）に移ると、拡張機能が自動でログインを戻します。自動で戻らないとき（ページが同じ URL のままのときや、パスキーの後にまだ手順が続くサイト）は、済んだら拡張機能のボタンを押すと、手でログインを戻せます。パスワード（1Password の拡張機能など）で外のブラウザからログインしたいときや、パスキーを求める前に WebView を止めるサイトでは、そのサイトのページでリーダーの `a` → `s` を押します。kisui-terminal が同じ URL を外のブラウザで開いて同じようにそのサイトを待つので、そこでログインしてページが移れば上と同じく自動で戻り、戻らなければ拡張機能のボタンを押します（シークレットのタブでは使えません）。拡張機能は [addons.mozilla.org](https://addons.mozilla.org/addon/kisui-terminal-passkey-login/) から入れます。一覧を変えたら kisui-terminal を起動し直してください。起動するたびに、使っている Firefox に native messaging の受け口を登録します。パスワードと認証アプリのコードは、移らずに内蔵ブラウザで入力できます。ログインを localStorage に置くサイトでは使えません。操作の画面の中でパスキーを求める操作は、外のブラウザで行います（GitHub は確認をしばらく覚えるので、外のブラウザで確認したあと内蔵ブラウザで続けられます）。Firefox から写した Google のログインが内蔵ブラウザで続くかは、確かめていません。Windows の Chrome は、ログインを端末に結び付ける Device Bound Session Credentials に対応しました（macOS はこれから）が、Firefox でしたログインに Google がそれを使うかは確かめていません。そのため `.google.com` は試すための書き方で、使えるという約束ではありません。詳しくは [docs/passkey-extension.md](docs/passkey-extension.md) にあります。
- `[gui.browser]`（macOS 14 以上）：内蔵ブラウザは、kisui-terminal が手元の Mac で動かすプロキシ（`127.0.0.1` だけで待ち受けます）を通ります。プロキシはサイトのアドレスを自分で引き、IPv6 に先につなぐので、IPv6 の無い回線で Cloudflare WARP を使っていても、Google にほかの国のサイト（`www.google.com.hk` など）へ移されず、HTTP/3 も使えます。全部のサイトが通り、シークレットのタブと新しい窓のタブも通ります。`localhost` と `127.0.0.1`（下の中継で開くリモートの `localhost`）は通りません。そのため、内蔵ブラウザで初めてタブを開くとき、kisui-terminal はこの Mac だけの鍵と `localhost` 用の証明書を作り、macOS がパスワードを聞いて、証明書をログインのキーチェーンで信頼させます。信頼は用途が SSL、名前が `localhost` のときだけで、証明書は CA ではありません。取り消すと、プロキシ無しで今までどおり使え、作った証明書と鍵を消し、もう聞きません（データのディレクトリの `browser-proxy-declined` を消すと、次の起動で聞き直します）。鍵はファイルに置かず、ログインのキーチェーンに置きます。kisui-terminal を更新したあと、新しい版が鍵を使ってよいかを macOS が聞くことがあります（「常に許可」で、その版では聞かれなくなります）。証明書の有効な長さは 1 年で、切れる 1 か月前に作り直してもう 1 度聞き、古いものを消します（そこで取り消すと、古いものを切れるまで使い、もう聞きません）。証明書の信頼を外し、証明書と鍵を消すには、kisui-terminal を終えてから次のコマンドを動かします（macOS がパスワードを聞きます）。次にタブを開くとき kisui-terminal はまた聞くので、プロキシを使わないなら取り消します。

  ```sh
  # あとで確かめるため、証明書を写しておく
  security find-certificate -c "kisui-terminal browser proxy" -p > /tmp/kisui-browser-proxy.pem
  # その名前の証明書をすべて信頼の設定ごと消し、鍵を消す
  for h in $(security find-certificate -a -c "kisui-terminal browser proxy" -Z | awk '/^SHA-256 hash:/ {print $3}'); do
    security delete-certificate -t -Z "$h"
  done
  security delete-generic-password -s "kisui-terminal browser proxy"
  # 失敗すれば（CSSMERR_TP_NOT_TRUSTED）、信頼は外れている
  security verify-cert -c /tmp/kisui-browser-proxy.pem -p ssl -s localhost
  rm /tmp/kisui-browser-proxy.pem
  ```

- `[gui.sidebar]` の `tabs-height`：`shj` が動いているとき、サイドバーのヘッダーの下を「タブ」「ファイルツリー」「CHANGES」の 3 段に分け、段ごとにその中だけでスクロールします。タブの段が使える高さの上限を、サイドバーの高さに対する %（10〜90 の整数）で書きます（既定は `tabs-height = 40`）。タブが少なければ中身の高さまで縮み、多ければタブの段の中でスクロールします。タブの段とファイルツリーの境目は、ドラッグか、リサイズモード（`Cmd+R` / `Ctrl+Shift+R`、`Tab` でこの境目を選んで `j` `k`）でも動かせます。ダブルクリック（リサイズモードでは `=`）でこの設定の値に戻り、動かした値は起動し直しても残ります。`shj` が動いていないときは、タブがサイドバーの高さを全部使います。タブを足したときや、タブを切り替えたときは、その行が見える所までタブの段をスクロールします。
- `[gui.shortcuts]`：リーダーを通さずに 1 回で押せるキー（近道）を、自分で足せます。`"キー" = "コマンド"` と書きます。たとえば `"Ctrl+Alt+N" = "workspace.new"`、`"Alt+J" = "pane.focus:down"`。キーは、修飾キー（`Cmd`・`Ctrl`・`Shift`・`Alt`。`Cmd`・`Ctrl`・`Alt` のどれかは要ります）を `+` でつなぎ、最後に 1 つのキーを書きます（今使っている OS で押すキーのまま）。コマンドは、リーダーの木の動きの名前です（`pane.focus:left`・`pane.split:right`・`workspace.new`・`workspace.nth:0`（1 番目のワークスペース）・`scale:in`・`clipboard.history` など。一覧は [docs/key-design.md](docs/key-design.md) の 4.3）。同じキーの既定の近道があれば、書いたほうが勝ちます。`"Cmd+D" = "none"` と書くと、既定の近道を消すだけです。リーダーのキーは変わりません。足した近道は、全部のキーの一覧（リーダーの `?`）に出ます。読めないキー・知らないコマンド・同じキーの 2 回書きは、右下のお知らせに出し、その近道だけ使いません。`config.toml` と `config.local.toml` に同じキーがあれば、`config.local.toml` が勝ちます。
- 画面の URL（波線が引かれる）は、`cmd + click` か `cmd + shift + click`（macOS 以外は `ctrl + click` か `ctrl + shift + click`）で開きます。内蔵ブラウザを使っていればワークスペースの新しいタブで、使っていなければ OS 既定のブラウザで開きます。`cmd + option + click`（macOS 以外は `ctrl + alt + click`。`shift` を足しても同じ）は、いつも OS 既定のブラウザで開きます。開くのは http と https の URL だけです。リモート（ssh）のマシンのターミナルに出た `localhost` 系の URL は、手元のブラウザだと手元の localhost に行ってしまうため、ssh の上で中継し（`kisui relay`）、手元のアドレスの URL を開きます。そのポートで誰も待っていなければ、ブラウザを開かずにそう出します。アプリがマウスの報告を有効にしている間（vim・tmux・htop・`shj` など）は、shift なしのクリックはアプリに届くので、`cmd + shift + click`（か `cmd + option + shift + click`）を使います。以前の版の `[gui]` の `url_open` は無視します。
- `[server]`：`idle_stop_days`（窓がつながっていない状態で `kisui serve` が待つ日数。既定 7、0 は止めない）、`pane_reach`（`"own"`（既定）か `"all"`。ペインの中で打った `kisui pane` のコマンドが、このマシンのどのペインに届くか。`"own"` は打ったペイン自身と、そこから開いたペイン。`"all"` はこのマシンの全部のペイン。`kisui serve` は使うたびに読むので、止めなくても変更が効く）、`start_dir`（新しいワークスペースのシェルを始めるフォルダ。有るフォルダの絶対パスか、`~` で始まるパス）、`shell`（新しいターミナルのシェル。シェルのファイルの絶対パスか、`~/` で始まるパス。引数は書けない。書いていなければ `$SHELL`、それも無ければ `/bin/sh`）。`shell` のファイルが無い・実行できないときも、`kisui serve` は起動し、代わりに `$SHELL` でターミナルを始める。警告は `kisui serve` のログ（`~/.local/state/shijimi-editor/serve.log`。`$XDG_STATE_HOME` があればその下）に、そのパスごとに 1 度書く。パスの形でない `shell`（`bash` のような名前だけ）は設定の間違いで、`kisui serve` は起動しない。`kisui serve` は、`start_dir` と `shell` をターミナルを始めるたびに読み直すので、変えても（消しても）、止めずに次のターミナルから効く。設定に間違いがある間は、最後に読めた値を使う。`idle_stop_days` は `kisui serve` の起動のときに読む。手元の PC の `[server]` の `start_dir` と `shell` は、「ローカル」のターミナルの始め方でもある：ウィンドウが、ターミナルを作るたびに読み直して手元の `kisui serve` に渡すので、変えると `kisui serve` を止めずに次のターミナルから効く（マシンのダイアログ `m` の `t` でも入れられる。`config.local.toml` に書く）。リモートのマシンの分は、手元の `[[gui.machines]]` の `start_dir` と `shell` で決める（上）。
- `[[db.connections]]`：`kisui serve` が接続して SQL を実行できる DB（MySQL と PostgreSQL）。`name`・`kind`（`"postgres"` か `"mysql"`）・`host`・`port`・`user`・`database`、書き込みを DB に断らせる `read-only = true` と、`tls`（既定は `"prefer"`。`"verify"` で DB の証明書を確かめ、自前の認証局は `tls-ca` に書く）。1 つの接続に、環境の変種を書けます（`[[db.connections.variants]]`：`local`・`dev`・`prod` など。変種ごとに `host`・`port`・`user`・`database`・`read-only` を変えられ、変種に書いていないものは接続のものを使います）。`[db.permissions.<名前>]` で権限を定義し（`run`：`"none"`（実行しない）・`"read"`（読むだけ）・`"free"`（自由）、`propose`：コーディングエージェントが DB のタブの入力欄に SQL を書いてよいか、`agent-user`：コーディングエージェントがログインする DB のユーザー）、接続か変種に、人の権限（`human-permission`）とコーディングエージェントの権限（`agent-permission`）を名前で指定できます（例：`local` では自由、`prod` では読むだけ）。指定しなければ、人は今までどおりに動き、コーディングエージェントは実行できません（コーディングエージェントは `kisui db` のコマンドで使います。上）。権限には、時間を決めて強めてよいことを書けます（`elevate-to`：強めた間に使う権限、`elevate-max`：一度に強められる時間の上限。`"30m"` など）。普段は読むだけで、たまに書き込む接続に使います。接続するマシンに書きます（リモートのマシンなら、そのマシンの `config.toml`）。この PC の接続は、接続を選ぶ窓から足す・直す・消すこともできます（`a`・`e`・`d`。`config.local.toml` に書き、パスワードは書きません。詳しくは [docs/database.md](docs/database.md)）。パスワードはここに書きません：キーチェーン（macOS）か `~/.pgpass`・`~/.my.cnf` から読むか、聞かれたときに入力します。実行した SQL は、接続ごと（変種があれば変種ごと）にそのマシンに残ります。詳しくは [docs/database.md](docs/database.md)。使うのは DB のタブです（下）。
- `ui-language`：kisui-terminal の表示の言語です。画面（窓）と `kisui` の両方に効きます（`en` か `ja`。書かない・この 2 つ以外の値のときは英語）。窓は起動時に 1 度だけ読むので、変えたら次に起動したときから変わります。`shj` の同じ名前の項目とは別に書きます。

**DB のタブ**。ワークスペースに、ターミナルのタブ・ブラウザのタブと並べて、DB のタブ（上の接続の 1 つにつなぐ MySQL / PostgreSQL のクライアント）を開けます。リーダーの `n` → `d`（かサイドバーのワークスペースの「+」のメニューの「DB」）で、窓がつないでいる全部のマシンの `kisui serve` から `[[db.connections]]` を集めた一覧の窓が出て、右にどのマシンの接続かが出ます（1 つも無ければ「接続がありません」）。変種のある接続は、変種ごとに 1 行（`名前 (変種)`）で出ます：環境はここで 1 回だけ選び、開いたタブの中では切り替えません。開いたタブはほかのタブと同じくサイドバーの行に並びます。DB につなぐのは、接続を書いたマシンの `kisui serve` なので、リモートのマシンの接続も、トンネル無しで ssh の上で使えます。タブの中では、上に SQL を打ち、`Cmd+Enter`（macOS）か `Ctrl+Enter`（Linux）で、選んだ部分を（選んでいなければ、カーソルのある 1 つの文を）実行すると（文は `;` で区切ります。文字列・コメント・`$$` の中の `;` は区切りにしません。選んだ部分に文が 2 つ以上あれば、上から 1 つずつ実行し、失敗した文で止めます。1 つのトランザクションではなく、文ごとにコミットされます）、下に結果が表で出て、その下に件数とかかった時間が出ます（NULL は灰色の斜めの字で出し、長い値は切ります。指すと全部が見えます）。結果は、結果の上に並ぶ結果のタブに出ます：実行すると、出している結果のタブに上書きします（タブが無ければ足します）。`Cmd+Option+Enter`（macOS）か `Ctrl+Shift+Enter`（Linux）で実行すると、新しい結果のタブに出すので、前の結果が残ります。文を 2 つ以上実行したときは、1 個までで、超えると左から閉じます。セルはクリックで選び、Shift+クリックかドラッグで範囲に広げ、`Cmd+C` / `Ctrl+C` でコピーできます（2 つ以上のセルは TSV でコピーします）。`SELECT` が 1 ページ（1000 行）より多くの行を返したら、表の下の「前へ」「次へ」（かリーダーの `a` の窓の `f`・`b`）で、ほかのページを出せます（ページごとに SQL をもう一度実行します。[docs/database.md](docs/database.md#what-a-statement-does)。ページの間で順が変わらないよう、`ORDER BY` を付けてください）。列の見出しをクリックする（か、その列のセルを選んで `s` を押す）と、データベースが全部の行をその列で並べ替えます（昇順 → 降順 → 元の順）。`SELECT` を `ORDER 件残ります。字を打って絞り込めます）の窓が出て、選ぶと SQL の入力欄に入れます（実行はしません）。キーチェーンにも `~/.pgpass`・`~/.my.cnf` にも無いパスワードを DB が求めたら（そこで見つけたものを DB が断ったときも）、窓が聞き、その要求に付けて送ります。パスワードはファイルに書きません（通ったものは、窓を閉じるまで、窓と `kisui serve` がメモリに覚え、見つけたものより先に使います。`kisui serve` は、窓がつながっていなくなると忘れます）。kisui-terminal を開き直すと、DB のタブと書きかけの SQL が戻ります（結果のタブは戻らないので、もう一度実行します）。表のセルを書き換える機能はありません（SQL を書いて変えます）。コーディングエージェントは、`kisui db propose`（上）で DB のタブの入力欄に SQL を書けます：あなたが実行するまで実行されず、入力欄に SQL があるときは、上書きの前に窓が聞きます。接続の権限（自分のものか、コーディングエージェントのもの。設定が `elevate-to` と `elevate-max` で許しているもの）を時間を決めて強めるには、DB のタブでリーダーの `a` → `p` を押し、権限を選んで時間（`30m`・`1h`）を打ちます。強めている間は、タブに何を強めているかと残りの時間が出て、時間が過ぎる（か `kisui serve` が止まる）と元の権限に戻ります。同じ窓の `P` で、時間の前に戻せます。強められるのはあなただけで、コーディングエージェントに強めるコマンドはありません。

**プロキシ**。Burp や Caido のように、タブの HTTP・HTTPS の通信を見て、要求を書き換えて送り直したり、要求を途中で止めて書き換えたりできます。ターミナルのタブかブラウザのタブを出して、リーダーの `x` → `p` を押すと、場所が左右に分かれ、右のパネルにそのタブの通信の一覧と、選んだ通信の要求と応答（ヘッダーと本文）が出ます（`j` `k` で選ぶ、`Tab` で要求と応答を切り替える、`Esc` でタブに戻る、`q` でパネルを閉じる）。プロキシに通るのは、選んだタブだけです。何もしなければ、どのタブも通りません。

- プロキシは `kisui serve` が動かします。ターミナルのタブは、そのタブのマシンの `kisui serve`（ssh のマシンのタブなら、そのマシンで動きます）、ブラウザのタブは手元の PC の `kisui serve` を使います。待ち受けるのは `127.0.0.1` だけで、ポートはタブごとに別です。合言葉は求めないので、ほかの人も使うマシンでは、そのマシンの別のユーザーも、プロキシが動いている間はそこを通して通信でき、その通信はあなたの通信と一緒にパネルに出ます。
- ターミナルのタブ：**このあとに**開いたペイン（分けたペインなど）に、`HTTPS_PROXY`・`HTTP_PROXY` と、プロキシの認証局を信じさせる変数（`SSL_CERT_FILE`・`CURL_CA_BUNDLE`・`REQUESTS_CA_BUNDLE`・`GIT_SSL_CAINFO`・`NODE_EXTRA_CA_CERTS` など）が渡ります。先に開いていたペインは変わりません（動いているシェルの環境変数は変えられません）。これらの変数を読まないプログラムは、プロキシを通りません。プロキシの変数は読むが、認証局の変数は読まないプログラムは、通らないのではなく、証明書のエラーで通信できなくなります。例：macOS の Go 製のプログラム（`gh`・`terraform` など。macOS の Go は証明書をキーチェーンで確かめ、`SSL_CERT_FILE` を見ません）、Java のプログラム。そういうプログラムを使うときは、そのタブを通すのをやめて（`x` → `s`）、新しいペインを開いてください。
- ブラウザのタブ：ページを、そのタブだけのディスクに残さないデータ（Cookie・ログイン）で、プロキシを通して読み直します（シークレットのタブと同じ形）。OS の WebView は、プロキシをタブごとではなくデータごとに決めるので、ほかのタブとログインを共有したまま、そのタブだけを通すことはできません。ログインが要るときは、そのタブの中でログインし直してください。このタブでは、WebView 自身は証明書を確かめません。このタブの通信はすべて `127.0.0.1` のプロキシに行き、行き先のサイトの証明書はプロキシが確かめます。macOS は 14 以降が要ります。
- HTTPS の中身を読むため、プロキシは自前の認証局で証明書を作ります。`kisui` は、初めて使うときにマシンごとに 1 つ認証局を作り、状態を置くフォルダに置きます（`~/.local/state/shijimi-editor/proxy-ca-key.pem`。読めるのは自分だけ。証明書は `proxy-ca.pem`）。OS には**入れません**。信じるのは、プロキシに通したペインとタブだけです。行き先のサイトの証明書は、プロキシが自分で確かめ、正しくなければ 502 を返します。
- 書き換えて送り直す：パネルで通信を選んで `e` を押すと、中身の場所が、その要求（メソッド・URL・ヘッダー・本文）を書き換える欄になります。`Cmd+Enter`（macOS）か `Ctrl+Enter`（Linux）で送り、`Esc` でやめます。送るのはプロキシ（`kisui serve`）で、送った要求と応答は、一覧の新しい行（`↻` の印）に出ます。応答はページやシェルには返りません。`Host` は URL から、`Content-Length` は本文から決まります。字でない本文と、圧縮した本文は、元のまま送ります。記録の上限で切れた本文は、元のままでは送れないので、書いた本文を送ります。
- 途中で止める：パネルで `i`（リーダーの `x` → `i` でも）を押すと、要求を止めるのが入ります。入れている間、そのタブの要求は、送る前に止まり、一覧に「止めている」（状態が `||`）と出て、ページやプログラムは待ちます。止めている要求を選んで、`f` でそのまま流す、`e` で書き換える（`Cmd+Enter` か `Ctrl+Enter` で、書いたものが元の要求の代わりに流れます）、`d` で捨てる（送らず、ページやプログラムには 502 が返ります）を決めます。決めるたびに、いちばん古い、止めている要求が選ばれるので、順に進められます。もう一度 `i` を押すとやめ、止めていた要求はそのまま流れます。パネルを閉じる・ターミナルのタブを通すのをやめる（`x` → `s`）・窓を閉じるときも、止めるのをやめ、止めていた要求はそのまま流れます（見えない所で待たせ続けないため）。ブラウザのタブを通すのをやめたときと、タブを閉じたときは、止めていた要求は流れずに切れます（送りません。ブラウザのタブは、ページをプロキシ無しで読み直します）。止めるのは要求だけで、応答は止めません。どのタブも、入れるまでは止めません。プロキシの側から、止めている要求をあきらめることはありません。ページやプログラムが待つのをやめたら、その行は失敗になります（HTTP/1.1 の、本文を読んでいない要求は、流すか捨てるまで「止めている」のまま残ります）。本文を見て書き換えられるのは、大きさが分かっていて 256 KiB までのときです。ほかは、そのまま流れます。
- パネルを閉じても（`x` → `c`）、タブは通したままで、記録を続けます（1 つのタブにつき 1000 件、本文は 1 つにつき先頭の 256 KiB まで）。`x` → `s` でやめます。ターミナルのタブは、新しいペインに変数を渡さなくなり（変数を持ったままのペインのために、プロキシは中身を読まずに中継を続けます）、ブラウザのタブは、プロキシ無しで読み直します。

`kisui proxy` は、同じプロキシを、窓を使わずに単独で動かします。ほかの端末に貼る `export` の行を出し、そのあと通信 1 つにつき 1 行を出します（`-v` でヘッダーと本文も出す。`--listen 127.0.0.1:8080` で待ち受ける場所を決める）。

```sh
kisui proxy
kisui proxy -v --listen 127.0.0.1:8080
```

**キャラクター（実験的）**。リーダーの案内を、キャラクターがターミナルの左端から右下の位置まで押して運んでくるようにできます。キャラクターは kisui-terminal に入っていません。画面を動かすマシンの、`config.toml` と同じフォルダの `mascot/<名前>/`（`~/.config/kisui-terminal/mascot/<名前>/`。nightly 版は、あれば `kisui-terminal-nightly/mascot/`。`$XDG_CONFIG_HOME` が絶対パスならそちらを使います）に、キャラクターごとに `mascot.toml` と画像（背景が透明な右向きの PNG）を置き、リーダーの `c` → `s` で選びます（`mascot/` の中のキャラクターを並べた窓が出て、選ぶと `config.local.toml` に書きます。`config.toml` には書きません。home-manager が置く読み取り専用のファイルのことがあるためです）。`c` → `r` で、今選んでいるキャラクターを、窓を開き直さずに読み直します（次にリーダーを開いたときから新しい絵になります）。設定ファイルの `[gui]` に `mascot = "<名前>"` と自分で書いて選ぶこともできます。書いていなければキャラクターは出ません。キャラクターを配る人は、zip を落として `mascot/<名前>/` に広げるスクリプトを配ってください。使う人はそれを kisui-terminal のターミナルで実行し、`c` → `r`（新しいキャラクターなら `c` → `s`）を押します。kisui-terminal はスクリプトを実行しません。`mascot.toml` には、場面ごとに、コマの画像のファイル（名前もコマの数も自由）・1 コマの時間（既定 200 ミリ秒）・くり返すか・動く速さ（既定 1 秒に 90px）を書きます。キャラクターは案内を運び、運び終えると一息つき、しばらく（既定 3 秒）経つと休憩の動き（コーヒーを飲む・椅子に座る、など）をランダムに選んで見せ、案内を Esc で閉じると、案内を右へ押して画面の外まで持っていきます（`[push]` の場面でコマと速さを決めます。書かなければ運ぶ場面のコマを、既定の 1 秒に 90px の速さで使います）。Esc 以外（リーダーのキーをもう 1 度押す・操作を実行する・一覧に無いキーを押す・窓のフォーカスが外れる）で閉じると、その場でさようならを 1 回再生して消えます（案内からダイアログを開いたときや、さようならの場面が無いときは、すぐ消えます）。形式・全部の場面・既定の値・キャラクターの配り方は [docs/mascot.md](docs/mascot.md) にあります。以前の版の決まった名前（`walk-1.png`〜`walk-4.png`・`stop.png`）は読みません。窓を開いたときと、リーダーの `c` → `s`・`c` → `r` を押したときに読みます。OS の「視差効果を減らす」が入っているときは、右下に止まって出て、閉じると（Esc でも）その場で消えます。運んでいる途中に Esc で閉じたときも、押していかず、キャラクターと案内はその場ですぐ消えます。リーダーの後のキーは、アニメーションを待たずにすぐ効きます。

キャラクターを作るための skill `make-mascot` があります。`mascot.toml` と、コマごとの画像の指示文を作ります（画像そのものは作りません。画像は好きな画像生成のサービスで作ってください）。コーディングエージェント用のプラグイン `kisui-mascot` として配っています。Claude Code：`/plugin marketplace add mm1995tk/kisui-terminal` のあと `/plugin install kisui-mascot --marketplace mm1995tk/kisui-terminal`。Codex：`codex plugin marketplace add mm1995tk/kisui-terminal` のあと `codex plugin add kisui-mascot@kisui-terminal`。

ssh 先では、kisui-terminal は聞いてから自分の `kisui` と `shj` を `~/.cache/kisui-terminal/<版>/` に入れます。その先の PATH の `shj` には触りません。

| `t`                  | 今のワークスペースのタブ一覧：`w` と同じワークスペースの窓を、右の列（今のワークスペースのタブ）にフォーカスを置き、今出しているタブを選んだ状態で開く。続けて押すキーは、その窓の中のキーになる：`j` `k` でタブを選ぶ・`Enter` で出す・`h` でワークスペースの列へ戻る・`Esc` で閉じる・`n` タブを作る（種類を聞く）・`x` 閉じる・`r` 名前を変える・`J` `K`（Shift+j・Shift+k）並べ替える・`m` 別のワークスペースへ移す（窓の中で `?` を押すと一覧が出る）。タブが無いワークスペースでは、左の列から始まる |
| `n`                  | タブを作る（どの種類のタブを出していても）：`w` `t` と同じワークスペースの窓を、今のワークスペースを選び、作るタブの種類を窓の下の段のボタンで出した状態で開く。`t` ターミナル（続けて名前を打って `Enter`。`Tab` か `↓` で別のマシンを選べる）・`b` ブラウザ（すぐ新しいタブのページを出す。検索窓とブックマークがある）・`B` シークレットのブラウザ・`d` DB（窓を閉じて、全部のマシンの接続の一覧を出す）。ボタンを押してもよい。`Esc` は種類を選ぶのだけをやめる。ターミナルとブラウザのタブを作ったあとは、窓は開いたままで、作ったタブを選んでいるので、`Enter` でそのタブを出す。内蔵ブラウザを使わないときは、ブラウザの 2 つは無い。ワークスペースが 1 つも無いときは、種類を出さずに窓を開く |
| `i`                  | お知らせ：`u` 新しい版に更新する（「新しい版があります」のカードの「更新して再起動」と同じ）、`d` 閉じる、`g` 最後に OS の通知を出したペインを前に出す、`o` 内蔵ブラウザが最後にダウンロードしたファイルを開く、`f` そのフォルダを表示する |
| `x`                  | プロキシ：`p` 今出しているタブ（ターミナルのタブかブラウザのタブ）のプロキシのパネルを開く（そのタブの HTTP・HTTPS を、記録するプロキシに通し始める）、`c` パネルを閉じる（タブは通したまま）、`s` 今のタブを通すのをやめる、`i` 今のタブの要求を、送る前に止める（パネルで 1 つずつ、流す・書き換える・捨てる）・止めるのをやめる |

リーダーを通さずに押せる近道もあります（`?` の一覧に、使っている OS のものが出ます）。`Cmd+Shift+W` / `Ctrl+Shift+W` はワークスペースの窓を開きます。`Cmd+D` / `Ctrl+Shift+D` と `Cmd+Shift+D` / `Ctrl+Shift+E` はペインを右と下に分け（左と上に近道はありません。`a` で開く窓の `s` `h` と `s` `k` を使います）、`Cmd+R` / `Ctrl+Shift+R` は大きさを変え、`Cmd+Shift+Enter` / `Ctrl+Shift+M` はほかのペインを隠し、`Cmd+Shift+H` / `Ctrl+Shift+H` はクリップボードの履歴、`Cmd+=` `Cmd+-` `Cmd+0`（Linux は `Ctrl+=` `Ctrl+0`）は表示の大きさを変えます。macOS では `Cmd+W` でペインを閉じます。次のキーは、`shj` やシェルが使うので、なくなりました。`Ctrl+Shift+矢印` と `Cmd+Option+矢印`（ペインの移動。リーダーを使います）、macOS の `Ctrl+Shift+M`、Linux の `Ctrl+-`（表示を小さくする。リーダーを使います）。

画像のペイン（`kisui open --pane` で開いたものと、`shj` から開いたもの）では、ペインにフォーカスがあるあいだ次のキーが効きます（リーダーには載せていません。`?` の一覧に出ます）。`+` / `=` で拡大、`-` で縮小、`0` でペインに収まる大きさに戻し、拡大中は `h` `j` `k` `l` か矢印で見える場所を動かし、`Esc` でターミナルへ戻ります。マウスでは、`Ctrl` + ホイールかトラックパッドのピンチで（ポインタの位置を中心に）拡大・縮小し、拡大中はドラッグで動かせます。画面全体の大きさを変えるキー（`Cmd+=` など）は修飾キーが付くので、重なりません。

ファイルツリー・変更一覧・動画のペインにも、フォーカスがあるあいだだけ効くその場所のキーがあります。そこで `?` を押すとその一覧が出ます（リーダーの `?` も、フォーカスがある場所のキーを、リーダーのキーの上に出します）。ファイルツリーでは、`c` で名前をコピー、`m` で「ここへ移動」（ターミナルで cd。フォルダの行だけ）、`.` か Menu キーで、選んでいる行に右クリックのメニューを開きます。これらは今まで右クリックのメニューにしかありませんでした。ダイアログの一覧（クリップボードの履歴、リモートを足すときの候補）では、`↓` `↑` と同じに、`Ctrl+J` / `Ctrl+K` で次・前の行を選べます。

ワークスペースを切り替える窓と DB のタブの窓の下には、今できる操作が全部、何に効くかの見出し付きの行で出ます（`Enter`・`Esc`・`j` `k` など、どの窓でも同じ意味のキーは出ません）。ほかのキーで一覧を動かす窓（マシンのダイアログ、マシンや移す先を選ぶ窓、ブックマークの一覧、クリップボードの履歴）の下には、基本の操作（選ぶ・決める・やめる）だけが出ます。どの窓でも、`?` を押すと、その窓で使えるキーの全部の一覧が出て、`Esc` で元の窓の、選んでいた行に戻ります。ブックマークの一覧とクリップボードの履歴では、絞り込みが空のときだけ `?` で一覧が出ます（打っている途中の `?` は、探す字になります）。

## 開発

Nix の devShell（Go・gopls・gomod2nix・git・Node.js・Rust。Linux では WebView のライブラリも）を使います。direnv があれば `.envrc` で自動で入ります。コマンドはどれもリポジトリの根で動かします。`go.mod`（サーバーの `kisui`）、`package.json`（Web 画面。ソースは `app/`）、`Cargo.toml`（Tauri の殻 `app/src-tauri` を member に持つ workspace）はどれも根にあります。

```sh
nix develop
npm ci                 # Web 画面（最初と、package-lock.json が変わったとき）
go test ./...          # kisui
npm test               # Web 画面
cargo test             # Tauri の殻
go build -o target/dev/kisui ./cmd/kisui   # 窓が起動する kisui（SHIJIMI_KISUI）
SHIJIMI_KISUI=$PWD/target/dev/kisui npm run tauri dev   # 動かす（devShell の外では nix run .#dev）
npm run storybook      # 部品を 1 つずつブラウザで見る。Tauri は要らない（docs/design/storybook.md）
nix fmt                # 全部を整形する
nix flake check        # CI が回す検査を全部（整形・go test・ビルドとテスト）
```

`tauri dev` では、ペインの中のターミナルは PATH の `shj` を使います。配るアプリは自分の `shj` を同梱します（`packaging/`）。

置き場：`app/` が窓（`src/` に Solid + TypeScript。中は `ui/`・`features/`・`infrastructure/` に分けています：[docs/design/frontend-structure.md](docs/design/frontend-structure.md)。`src-tauri/` に Tauri の殻）、`cmd/kisui` と `server/`・`attach/`・`rpc/`・`config/` が `kisui`（Go）、`internal/` は kisui が持つ `shj` との取り決め（`ctl`）・PTY（`term`）・ビルドの情報（`buildinfo`）・メッセージ（`i18n`）です。`docs/design/` は設計の経緯です。

リリースの流れは [docs/releasing.md](docs/releasing.md) にあります。
