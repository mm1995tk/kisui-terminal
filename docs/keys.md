# kisui-terminal のキー操作とマウスの操作の一覧

kisui-terminal の窓（`app/`）が受けているキー操作と、マウスでしかできない操作を、コードから洗い出した表。キー操作を作り直すときの土台にする。この文書は今のコードを並べただけで、キーを決める文書ではない。

- 新しいキー操作の表（リーダーと近道。#91 で決めた）は [`key-design.md`](key-design.md)。
- 書いたのは、`main` の d20d4db の時点。1.1・1.2 は #92（リーダーと案内）のあとの状態に直した。ほかの章の「定義の場所」の行番号は、そのときのまま。キーを足す・変えたら、この表も直す。#313 で `app/src/` の配置を変えたので、パスは新しい場所に直した（行番号はそのまま。`App.tsx` にあったものは、分けた先のファイルと関数の名前で書いた）。
- 「定義の場所」は `path:行`。`app/src/` の下のファイルは `app/src/` を省いて書く。1.1・1.2 のキーは `features/commands/commands.ts` の表が定義なので、行は書かない。
- キーは、窓の外の GUI（`app/`）が受けるものだけを書く。Go の `kisui`（`kisui serve`・`kisui attach`）にはキーの割り当てが無い。
- 洗い出しかた：`keydown` を受けている所（`git grep -nE "keydown|onKeyDown" app/src`）と、`metaKey`・`ctrlKey`・`altKey` を見ている所を全部たどった。`app/src-tauri/src` でキーを取るのは、`clipboard_popup.rs` の全体のキーと、`menu.rs` の差し替えたメニューの「閉じる」（Mac だけ。Cmd+W）の 2 つ。
- 「Mac」は macOS、「Linux」は Linux と Windows（Mac 以外）。Cmd は Mac の ⌘、Option は Mac の ⌥。

## 1. キー操作

### 1.1 全体（どこにフォーカスがあっても効く）

`features/commands/commands.ts` のコマンドの表が、リーダーと近道を持つ。`ui/main-window/keys.ts` の `onGuiKey` が `window` の `keydown` を capture（ペインに届く前）で受け、表の `route` に渡す。表のキーに当たったキーは `preventDefault` と `stopPropagation` をして、シェルにも shj にも送らない。当たらないキーは何も受けず、今までどおりターミナル（shj やシェル）に届く（リーダーに入っている間だけは、一覧に無いキーも捨てて出る）。

リーダー（Mac は Cmd+K、Linux は Ctrl+Shift+K）を押すと、次に押せるキーの一覧が画面の右下に出る（`ui/main-window/commands/LeaderMenu.tsx`。右下のお知らせのカードより手前に重なる）。案内の文は短くしてあり（「左のペインへ」「ワークスペースを作る」など）、補足は下のリーダーの説明に書く。Mac では `v`（表示の大きさ）のグループを案内に出さない（Cmd+= / Cmd+- / Cmd+0 が共通の操作のため）。Linux では出す（Ctrl+- が端末の Ctrl+_ と同じ信号で近道が無く、`v -` しか小さくするキーが無いため）。向きの `h` `j` `k` `l` は 1 行にまとめる（`h|j|k|l  ペインを移動`。ワークスペースの中だけ `j|k` と `h|l` の 2 行）。`?` の一覧は、どの OS でも全部出す。`?` の一覧も案内と同じく、同じ操作の向き違いを 1 行にまとめる（`h|j|k|l`）。まとめた行に設定で近道を足すと、どのキーのものかを添えて並べる（`Alt+J (j)`）。リーダーの木に無い操作のうち近道があるもの（ペインを分ける Cmd+D など。下の表の「リーダー」が `a` の窓のもの）は、木のあとの「Shortcuts only」の行に並ぶ（#457）。説明文と列見出し（「リーダーの後に押すキー・操作・近道」）は、一覧をスクロールしても上に残る。リーダーの木と、そこへの近道は `key-design.md` の 3 章・4 章。`?` で全部のキーの一覧（`ui/main-window/commands/KeyListDialog.tsx`）が出る。

プロキシ（#409。今出しているタブの HTTP・HTTPS の通信を記録して見る。`features/proxy/`・`ui/main-window/content/proxy/`。有効にする設定は無い）の操作は、リーダーの `x` のグループにある：プロキシのパネルを開く（`x p`。グリッドの場所が左右に分かれ、右に通信の一覧と、選んだ通信の要求と応答（ヘッダーと本文）が出て、キーがパネルに移る。まだ通していないタブなら、ここで通し始める。ターミナルのタブは、そのマシンの `kisui serve` が、このあとに開いたペインに `HTTPS_PROXY`・`HTTP_PROXY` と、プロキシの認証局を信じさせる変数（`SSL_CERT_FILE`・`NODE_EXTRA_CA_CERTS`・`REQUESTS_CA_BUNDLE` など）を渡す。先に開いていたペインと、変数を読まないプログラムは通らない。ブラウザのタブは、ページを、そのタブだけのディスクに残さないデータで、プロキシを通して読み直す（共有のログインは見えないので、通したタブの中でログインし直す）。もうパネルが出ていれば、キーをパネルに向けるだけ）・パネルを閉じる（`x c`。通したままで、記録は続く）・今のタブを通すのをやめる（`x s`。パネルも閉じる）。パネルにキーがある間は、`j` `k`・`↓` `↑` で通信を選び（`g` `G` で先頭と末尾）、`Tab`（`h` `l`・`←` `→` でも）で中身の「要求」と「応答」を切り替え、`Esc` でキーをタブに戻し（パネルは出したまま）、`q` でパネルを閉じ、`?` でパネルのキーの一覧を出す（`features/proxy/keys.ts` の `proxyPanelKey`）。`e` で、選んでいる通信の要求を書き換える欄を開く（#410。中身の場所が、メソッド・URL・ヘッダー・本文の欄になる）。欄では Cmd+Enter（macOS）・Ctrl+Enter（ほか）で、書き換えた要求を `kisui serve` のプロキシから送り直し（送った要求と応答は、一覧の新しい行に出て、その行が選ばれ、応答の側が出る。ページやシェルには返さない）、`Esc` で書き換えをやめる（`features/proxy/keys.ts` の `proxyEditKey`。欄の字はパネルのキーにしない）。通信を途中で止める（#411）には、`i`（リーダーの `x i` でも）で、要求を行き先に送る前に止めるのを入れる。入れている間、そのタブの要求は、一覧に「止めている」（状態が `||`）と出て選ばれ、`f` でそのまま流す・`e` で書き換える欄を開いて Cmd+Enter・Ctrl+Enter で書き換えたものを流す・`d` で捨てる（行き先に送らず、ページやプログラムには 502 が返る）を決めるまで待つ。流す・捨てると、次に古い、止めている要求が選ばれる。もう一度 `i` でやめると、止めていた要求はそのまま流れる。パネルを閉じる・ターミナルのタブを通すのをやめる・窓を閉じると、止めるのもやめて、止めていた要求はそのまま流れる（ブラウザのタブを通すのをやめたとき・タブを閉じたときは、止めていた要求は流れずに切れる）。止めるのは要求だけで、応答は止めない。記録は `kisui serve` が持ち、1 つのタブにつき 1000 件・本文 1 つ 256 KiB までで、古いものから捨てる。認証局は OS に入れず、マシンごとに 1 つを `kisui serve` の状態のフォルダに置く。窓を使わずに端末だけで見るには、`kisui proxy` を使う。

**ユーザーが足す近道**（#199）：設定ファイルの `[gui.shortcuts]` に `"Ctrl+Alt+N" = "workspace.new"` のように書くと、そのキーで 1 回でコマンドを動かせる（コマンドの名前・間違いの扱い・既定の近道との重なりは `key-design.md` の 4.3）。足した近道は、`?` の一覧（リーダーの `?`）の、そのコマンドの行の「近道」に出る（リーダーの木に載せないコマンドに足した近道は、木のあとの「Shortcuts only」の行に出る。#457）。同じキーの既定の近道は、設定のほうが勝つ。コマンドに `none` と書くと、そのキーの既定の近道を消す。

## 3. 気づいたこと（表を作って分かったもの。変える・変えないはこの Issue では決めない）

この章は、#92 より前のコードを見て書いたまま残してある。#92 で、リーダーに入れたキー（ワークスペースを閉じる・マシンの操作・ワークスペースを作る・Linux の分割したペインを閉じる操作）はキーでできるようになり、Mac の Ctrl+Shift の別名・Ctrl+Shift+矢印・Linux の Ctrl+`-` は消えた。

- Mac と Linux で形が違う：分割は Mac が Cmd+D / Cmd+Shift+D、Linux が Ctrl+Shift+D / Ctrl+Shift+E。Cmd+W（分割したペインを閉じる）は Mac だけで、Linux には同じ操作のキーが無い。リサイズモードに入るのは Cmd+R / Ctrl+Shift+R。
- Mac でも効く Ctrl+Shift の形がある：Ctrl+Shift+矢印（ペインの移動）と Ctrl+Shift+M（ペインを隠す）は Mac でも受ける（`directionKey`・`isZoomKey` は `isCtrlShift` を Mac でも見る）。分割とリサイズに入るキーは Mac では Ctrl+Shift の形を受けない。
- キーでできないもの：ワークスペースを閉じる・マシンを足す・マシンを切る／外す／名前を変える・つなぎ直す・ワークスペースを作る・動画のペインとファイルのペインの ×（ペインを閉じる）・Linux の分割したペインを閉じる操作・ペインどうしのフォーカス移動以外のペインの選択は、マウスだけ（2 の表）。
- 同じ字のキーが場所ごとに別の意味：`j` `k` `l` `h` はツリー・CHANGES・リサイズモードで移動、動画のペインでは `j` `l` が 10 秒の移動、`k` が再生・停止。`r` はツリーでは名前の変更、CHANGES では読み直し、リサイズモードでは何もしない。`Esc` はツリーでは端末へ戻る、CHANGES では一覧を出る、窓・メニューでは閉じる、リサイズモードでは出る。
- 全体のキーが、ターミナルのペインの外（ツリー・CHANGES・動画のペイン・窓の中）でも効くものと、ペインの中だけで効くもの（ペインの移動・Cmd+W）が混ざっている。
- `Ctrl`+`-`（Linux の表示を小さく）は、端末の `C-_`（readline の undo）を奪う（`features/scale/scale.ts:25` に承知の上と書いてある）。
