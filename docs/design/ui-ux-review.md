# UI/UX の点検と共通ルール（窓の画面）

kisui-terminal の窓（`app/src/`）の表示と操作を、画面をまたいで点検した結果と、そこから決めた共通ルール。#306 で作った。

- 値と部品の決まりは [design-system.md](design-system.md)、キーの割り当ては [`../key-design.md`](../key-design.md) と [`../keys.md`](../keys.md)、コードの置き場は [frontend-structure.md](frontend-structure.md)。この文書は、それらをまたぐ「同じ役割のものを、同じ意味・見た目・手順にする」ための決まりと、まだそろっていない所の一覧を持つ。
- 点検の基準は main の `6b79d1a`（2026-11-19）。パスは `app/src/` からの相対。
- 画面を足す・直すときは、4 章の共通ルールに合わせる。合わせられない理由があれば、3 章の「意図した差」に足す。

## 2. 区分

3 章の各項目に、次のどれかを付ける。

| 区分           | 意味                                                                 |
| -------------- | -------------------------------------------------------------------- |
| そろえた       | 合意済みの方針で、実装までした                                       |
| コード上の差   | 同じ役割なのに、コードの上で違いがある。そろえる案は 5 章            |
| 意図した差     | 役割・入力欄の有無・壊す操作かどうか・OS の慣習から来る差。理由を残し、変えない |
| 未確定         | どちらに寄せるかを、オーナーが決める必要がある。案は 5 章            |

実行画面で見つけた不統一は、まだ無い（1 章）。見つけたら、この章の区分に「実行画面」を足して 3 章に書く。

## 3. 点検の結果

優先度は、高（同じ操作の結果や安全さが入口で変わる）・中（覚え直しが要る・意味を取り違えうる）・低（見た目だけ）。

### 3.1 ヒントとヘルプ（そろえた）

- **前の状態**：窓の下のヒントが窓ごとに違った。マシンのダイアログは 8 項目、切り替える窓は列ごとに 9〜10 項目と、ドラッグの説明の文。ブックマークの一覧とクリップボードの履歴は、入力欄の下に「·」でつないだ 1 文。`?` で詳しい一覧が出るのは、マシンのダイアログとブックマークの一覧だけで、出る一覧はリーダーの木の全部（その窓が出ている間は使えない）に、その窓のキーを足したものだった。
- **再現する操作**：リーダー `m`・`w`・`o B`（#459 からは、ブラウザのタブでリーダー `a` → `B`）・`y`・`t m`（#454 からはリーダーに無い。設定の近道の `tab.moveTo`）・`c s` で、それぞれの窓を開いて下の段を見比べる。
- **利用者への影響**：同じ「選ぶ・決める・やめる」が、窓ごとに違う場所・違う字・違う順で出る。操作の多い窓ではヒントが 2〜3 行になり、基本の操作が埋もれる。
- **そろえ方**（4.7 の決まり）：下の段（共通フッタ）には基本操作だけを、どの窓でも同じ順・同じ字で出す。詳しい操作は `?` で出す。`?` の一覧は、その窓のキーだけを出す。
- **根拠**：`ui/components/KeyFooter.tsx`、`features/commands/placeKeys.ts` の `basicHints` と `PLACE_KEYS`、`ui/main-window/commands/KeyListDialog.tsx`。
- **優先度**：中。

まだ文のままのヒント（そろえていない。5 章の案 G）：

| 所                               | 今の出し方                                         | 根拠                                             |
| -------------------------------- | -------------------------------------------------- | ------------------------------------------------ |
| ページ内検索の帯                 | 「Enter で次・Shift+Enter で前・Esc で閉じる」の 1 文 | `content/browser/FindBar.tsx` の `find.hint`     |
| 新しいタブのページ               | 検索窓の下の 1 文                                  | `content/browser/NewTabPage.tsx` の `newTab.hint` |
| リモートを足す窓                 | 候補を選ぶキー（`↓` `↑`・Ctrl+J / Ctrl+K）の案内が無い | `sessions/AddMachine.tsx`                        |
| キーの一覧                       | 下の段は「閉じる」のボタンだけ（`Esc` の案内は無い）。表の色はパレットを直に読む | `commands/KeyListDialog.tsx`・`KeyListDialog.module.css` |
| 確認の窓・ssh の質問・ファイル転送 | ボタンだけ（`Enter`・`Esc` の案内は無い）           | 4.4 の決まりどおり。意図した差                   |

### 3.2 入力エラーと失敗の色（未確定）

- **現状**：
  - 名前を変えて断られた理由は、どこでも警告の色（`--state-warning`。黄）。サイドバーの帯（`sidebar.css` の `.band-rename-error`）も、その場の入力欄（`inline-input.css` の `.inline-error`）も同じ。#306 を書いた時点では、サイドバーだけ赤だった。今はそろっている。
  - 窓のエラーの文（`card.css` の `.card-error`）も警告の色。削除できなかった・リモートを足せなかった・更新に失敗した、のような「できなかった」にも使う。
  - 内蔵ブラウザの入力欄（URL バー・新しいタブのページ・ページ内検索）は、失敗の赤（`browser.css` の `--gh-red`）。
- **再現する操作**：サイドバーでワークスペースの名前を 101 字以上にして Enter（黄）。URL バーに `ftp://example.com` を入れて Enter（赤い枠）。ページ内検索で見つからない語を打つ（赤い字）。
- **利用者への影響**：「入れた値が受け付けられなかった」が、場所によって黄と赤に分かれる。`design-system.md` は、警告を「続けられるが気をつける」、失敗を「できなかった」と決めているが、窓のエラーの文は「できなかった」のに警告の色。
- **案**：5 章の案 B。
- **優先度**：中。

### 3.3 閉じる・削除・切断の確認（未確定）

| 操作                         | 入口                                             | 確かめ方（今）                                            | 根拠                                                    |
| ---------------------------- | ------------------------------------------------ | --------------------------------------------------------- | ------------------------------------------------------- |
| ワークスペースを閉じる       | サイドバーの見出しの ✕                           | 聞かずに閉じる。動いているプログラムがあれば確認の窓      | `sidebar/workspaces/BandHeader.tsx`、`features/workspaces/controller.ts` の `closeWorkspace` |
| 同上                         | 切り替える窓の `x`・行の ✕                       | その行で `y` / `n` を聞く。その後、動いているプログラムがあれば確認の窓（2 回聞く） | `workspaces/WorkspaceSwitcher.tsx` の `startClose` |
| タブを閉じる                 | サイドバーの行の ✕・切り替える窓の `x`・リーダー `t x`（#454 からは、リーダー `t` の窓の `x`） | 聞かずに閉じる。動いているプログラムがあれば確認の窓      | `features/workspaces/tabs/controller.ts` の `closeTermTab` |
| マシンを一覧から外す         | マシンのダイアログの `d`・見出しのメニュー       | 聞かずに外す（接続は切るが、マシン側の kisui serve とタブは残る） | `features/sessions/controller.ts` の `removeFromSidebar` |
| マシンを切る                 | マシンのダイアログの `x`・右下の知らせ           | 聞かずに切る（つなぎ直せる）                              | 同上の `disconnect`                                     |
| ファイル・フォルダを削除する | ファイルツリーの `d`・メニュー                   | 確認の窓（フォルダは「中身も消える。元に戻せない」と出す） | `sidebar/file-tree/TreeDialogs.tsx`                     |
| ブックマークを消す           | ブックマークの一覧の Ctrl+D                      | 聞かずに消す                                              | `features/browser/bookmarksStore.ts`                    |

- **再現する操作**：タブが 2 つあるワークスペースを、サイドバーの ✕ と、切り替える窓の `x` で閉じて比べる。
- **利用者への影響**：同じワークスペースを閉じるのに、入口で確認の回数が違う。サイドバーの ✕ は、押し違いでタブをまとめて閉じる（シェルだけなら確認なし）。
- **意図した差として残すもの**：切る・外すは、つなぎ直せる・足し直せるので聞かない。ファイルの削除は元に戻せないので必ず聞く。
- **案**：5 章の案 A。誤操作を防ぐ手順を弱める変更になりうるので、合意してから直す。
- **優先度**：高。

### 3.4 フォーカス・選択・所属マシン・接続の状態（未確定）

| 所                                   | キーが向く先の見せ方                                   | 根拠                                    |
| ------------------------------------ | ------------------------------------------------------ | --------------------------------------- |
| 窓のボタン・一覧の行                 | 青い枠 2px（`--state-focus-ring`）                     | `button.css`、`card.css`                |
| サイドバーの帯・タブの行のボタン     | マシンの色の内側 1px の枠                              | `sidebar.css` の `.band-btn:focus-visible` ほか |
| ファイルツリー・CHANGES の行         | マシンの色の内側 1px の枠                              | `tree.css`、`changes.css`               |
| 「ワークスペースを作る」・幅の広いボタン | 接続が正常の色（緑）の内側 1px の枠                 | `sidebar.css` の `.new-workspace:focus-visible`・`.band-btn-wide:focus-visible` |
| 内蔵ブラウザの入力欄                 | 青い枠 1px（パレットを直に読む）                       | `browser.css`                           |
| 切り替える窓                         | 枠は出さず、効いている列の選んでいる行の左端に色の線   | `switcher.css`                          |

- **利用者への影響**：`design-system.md` は、所属マシン・接続の状態・フォーカス・選択の 4 つを別の値で表すと決めている。サイドバーでは、フォーカスをマシンの色や接続の色で表すので、「緑の枠」が接続の状態に見えうる。
- **意図した差として残すもの**：マシンの色そのもの（どのマシンのものかを表す）。ターミナルのペインの境界と段の境目が、動かしている間マシンの色で光ること。
- **案**：5 章の案 C。
- **優先度**：中。

### 3.5 境界（つかむ所と反応）（コード上の差）

| 境界                             | 当たり     | いつも見える印          | ポインタを乗せたとき             | 動かしている間      | 根拠                     |
| -------------------------------- | ---------- | ----------------------- | -------------------------------- | ------------------- | ------------------------ |
| ターミナルのペインどうし         | 帯の幅     | 1px の線                | マシンの色に変わり、太くなる     | マシンの色          | `terminal.css` の `.terminal-bar` |
| サイドバーと右のペイン           | 幅 4px     | 無し（ブロックの縁の線） | 変わらない（カーソルだけ）       | マシンの色          | `layout.css` の `.resizer` |
| タブの段とファイルツリーの段     | 高さ 6px   | 2px の線と真ん中の短い棒 | 変わらない（カーソルだけ）       | マシンの色          | `sidebar.css` の `.tabs-resizer` |
| ファイルツリーと CHANGES         | 高さ 6px   | 同上                    | 変わらない（カーソルだけ）       | マシンの色          | `changes.css` の `.changes-resizer` |

- **そろっている所**：段の境目 2 つは、#303 で同じ見た目（2px の線と短い棒）・同じ当たり（6px）にそろえた。動かしている間の色は 4 つとも同じ。
- **残る差**：ポインタを乗せたときに光るのは、ターミナルのペインの境界だけ。サイドバーの境界は、印も反応も無く、当たりも 4px でいちばん狭い。
- **利用者への影響**：サイドバーの幅を変えられることに、カーソルが変わるまで気づけない。
- **案**：5 章の案 D。
- **優先度**：低。

### 3.6 入力に失敗したときの説明（コード上の差）

| 所                                         | 伝え方                                                        | キーボードだけで読めるか |
| ------------------------------------------ | ------------------------------------------------------------- | ------------------------ |
| その場の入力欄（名前を変える・作る）       | 入力欄の下に理由の文（`role="alert"`）。入力欄は開けたまま     | 読める                   |
| 窓の入力（リモートを足す・削除の確認）     | 窓の中に理由の文（`CardError`、`role="alert"`）                | 読める                   |
| ページ内検索                               | 帯の中に「見つかりません」（`role="status"`）                  | 読める                   |
| URL バー・新しいタブのページ               | 赤い枠と `aria-invalid`。理由は `title`（ポインタを乗せると出る） | **読めない**（画面に文が出ない） |
| マシンのダイアログ・キャラクターを選ぶ窓   | 操作できない理由を、下の段のヒントの上に出す（`role="alert"`）   | 読める                   |

- **再現する操作**：URL バーに `ftp://example.com`（http・https でないもの）を入れて Enter。枠が赤くなるが、理由の文は出ない。
- **案**：5 章の案 E。
- **優先度**：中。

### 3.7 行の押し方と、使えない操作の伝え方（意図した差・一部は未確定）

行を 1 回押したときの動き：

| 所                                   | 1 回押す                         | 決める                               |
| ------------------------------------ | -------------------------------- | ------------------------------------ |
| サイドバーのタブの行・ファイルツリー・CHANGES | 開く（移る）              | —                                    |
| 一覧から選ぶ窓・マシンのダイアログ   | 選ぶだけ                         | ダブルクリックか `Enter`             |
| ブックマークの一覧・クリップボードの履歴 | 選ぶだけ（フォルダは開け閉め） | ダブルクリックか `Enter`             |
| 切り替える窓                         | 選ぶだけ                         | 選んでいる行をもう 1 回押すか `Enter` |

- **意図した差**：サイドバーとツリーは、いつも出ている「移るための一覧」で、押せばすぐ移る。窓は、選んでから決める（選んだ行に操作のキーが効くため）。
- **未確定**：窓の中で「決める」マウスの手順が 2 通りある（ダブルクリックと、選んでいる行をもう 1 回）。5 章の案 F。

使えない操作の伝え方：

| 所                               | 伝え方                               | 根拠                                         |
| -------------------------------- | ------------------------------------ | -------------------------------------------- |
| サイドバーの帯・タブの行のボタン | 出さない（場所は空けておく）         | `sidebar.css` の `.band-btn[data-off]`       |
| 見出しのメニューの項目           | 薄くして押せなくする                 | `sidebar.css` の `.machine-menu-item:disabled` |
| マシンのダイアログのキー         | 押したときに、理由を下の段に出す     | `features/sessions/machineList.ts` の `canDo` |
| キャラクターを選ぶ窓の行         | 行に「使えません」、決めようとすると理由 | `mascot/MascotDialog.tsx`                 |
| 窓のボタン                       | 薄くして押せなくする（`disabled`）   | `button.css`                                 |

- **意図した差**：行のボタンは場所が狭く、理由を出せないので出さない。キーの操作は「押せるかどうか」を先に見せられないので、押したときに理由を出す。
- **優先度**：低。

### 3.8 同じ名前を変える操作のキー（未確定・キーの変更は未合意）

| 所                             | 名前を変える | そのキーのほかの意味（同じ所）       |
| ------------------------------ | ------------ | ------------------------------------ |
| マシンのダイアログ             | `n`          | `r` はつなぎ直す                     |
| 切り替える窓（ワークスペース・タブ） | `r`    | `n` は作る                           |
| ファイルツリー                 | `r`          | `n` はファイルを作る                 |
| リーダー                       | `t r`（タブ）・`o R`（ブラウザのタブ）（#454・#459 からは、どちらもリーダー `t` の窓の `r`） | —              |

- **利用者への影響**：名前を変えるのは 4 か所のうち 3 か所で `r`。マシンのダイアログだけ `n` で、そこでは `r` がつなぎ直す。切り替える窓の `n`（作る）に慣れた手でマシンのダイアログの `n` を押すと、名前の入力欄が開く（壊す操作ではない）。
- **今の補い方**：どの窓でも `?` でその窓のキーの一覧が出る（3.1）。
- **案**：5 章の案 H。キーを変えるので、合意してから。
- **優先度**：中。

### 3.9 窓の閉じ方（コード上の差）

- 窓は `Esc` で閉じる。右上の ✕ は置かない（`design-system.md`）。**クリップボードの履歴だけ、見出しの右に ✕ がある**（`ui/modules/clipboard-history/HistoryPanel.tsx`。外から開く小さな窓でも使うため）。
- 窓の外を押して閉じるのは、切り替える窓だけ（`closeOnOutside`）。一覧から選ぶ窓・マシンのダイアログ・ブックマークの一覧は、打ちかけの入力が無いのに閉じない。
- マウスで閉じる手段：一覧から選ぶ窓・マシンのダイアログは下の段のボタン、履歴は ✕、切り替える窓は外を押す、**ブックマークの一覧には無い**（`Esc` だけ）。
- **案**：5 章の案 F。
- **優先度**：中（ブックマークの一覧を、マウスだけでは閉じられない）。

### 3.10 選ぶ行を動かすキー（コード上の差）

- 一覧から選ぶ窓とマシンのダイアログは、`j` `k`・矢印・`g` `G`・`Home` `End`・Ctrl+J / Ctrl+K を受ける。切り替える窓は `g` `G`・`Home` `End` を受けない（`workspaces/switcherKey.ts`）。
- **案**：5 章の案 F に含める（足すだけ。ほかのキーとぶつからない）。
- **優先度**：低。

## 4. 共通ルール

「決まり」は、今の実装が従っているもの。新しく作る所も従う。「未確定」は 5 章の案が決まるまで、今のままにする。

### 4.1 色と状態

- 決まり：色は役割の名前（`tokens.css`）で選ぶ。状態は `design-system.md` の「状態」の表の意味で使う。
- 決まり：名前の入力が断られた理由は、どこでも同じ色（今は警告の色）・同じ場所（入力欄のすぐ下）に出す。
- 未確定：「入れた値が受け付けられなかった」と「操作ができなかった」を、警告の色にするか失敗の色にするか（案 B）。

### 4.2 フォーカスと選択

- 決まり：所属マシン・接続の状態・フォーカス・選択は別の意味で、新しく作る所では別の値で表す（`design-system.md`）。
- 決まり：窓の一覧は、選んでいる行を 1 つ持ち、キーはその行に効く。フォーカスは一覧（か入力欄）に置いたままにし、行には移さない（`aria-activedescendant`）。
- 未確定：サイドバー・ファイルツリー・CHANGES のフォーカスの枠の色（案 C）。

### 4.3 ボタンと入力

- 決まり：窓のボタンは `Button`。主の操作は 1 つで右端。やめる・閉じるは左（`design-system.md`）。
- 決まり：名前を変える・作るは、窓を出さず、その行をその場の入力欄にする（`InlineInput`）。
- 決まり：入力が断られたら、入力欄を開けたまま、理由を文で出す（色だけ・`title` だけで伝えない）。URL バーと新しいタブのページは、まだ従っていない（案 E）。

### 4.4 確定と取り消し

- 決まり：`Enter` は決める、`Esc` はやめる（閉じる）。日本語の変換を確定する `Enter` と、変換をやめる `Esc` では動かさない（`isComposingKey`）。
- 決まり：`Esc` は、いちばん内側のものだけをやめる。その場の入力欄 → 行の中の確認（`y` / `n`）・つかんだタブ → 窓、の順。窓の `?` の一覧を `Esc` で閉じても、下の窓は閉じない。
- 決まり：確認の窓（閉じる・入れる・許す・削除）と、入力して送る窓（ssh の質問・リモートを足す）は、ボタンが案内を兼ねる（主ボタンが `Enter`、「やめる」が `Esc`）。下の段にキーのヒントは出さない。
- 決まり：ユーザーの操作と関係なく開く窓は、フォーカスを窓そのものに置き、打っていた `Enter` がボタンを押さないようにする（`focusSelf`）。

### 4.5 閉じる・削除・切断

- 決まり：元に戻せない操作（ファイルの削除）は、必ず確認の窓で聞く。
- 決まり：動いているプログラムがあるターミナルを閉じるときは、入口によらず確認の窓で聞く。
- 決まり：戻せる操作（切る・一覧から外す・ブックマークを消す）は聞かない。
- 未確定：ワークスペースを閉じる前に、プログラムが動いていなくても聞くか（案 A）。

### 4.6 境界

- 決まり：動かしている境界（ドラッグ中・リサイズモードで選んでいる間）は、マシンの色で光らせる。
- 決まり：段の境目は、2px の線と真ん中の短い棒（#303）。
- 未確定：ポインタを乗せたときの反応と、サイドバーの境界の印（案 D）。

### 4.7 ヒントとヘルプ

窓（真ん中に出す `ModalCard`）のうち、キーで一覧を動かすものが対象。

1. **下の段（共通フッタ）には、基本操作だけを出す。** 基本操作は 5 つの役割で、この順に並べる：選ぶ（`j` `k`。入力欄に字を打つ窓は `↓` `↑`）→ 移る（列を移る `h` `l`。ある窓だけ）→ 決める（`Enter`。あるときだけ）→ `?`（キーの一覧）→ やめる・閉じる（`Esc`）。
2. **同じ役割には同じ字を使う。**「選ぶ」「キーの一覧」「やめる」「閉じる」は共通。`Enter` の字だけ、その窓ですること（「作る」「移す」「貼る」など）を書く。`Esc` は、決めずにやめる窓（一覧から選ぶ窓）では「やめる」、見終えて閉じる窓（マシンのダイアログ・切り替える窓・ブックマーク・履歴）では「閉じる」。
3. **詳しい操作は `?` で出す。** 作る・名前を変える・閉じる・並べ替える・消す、`g` `G`、Ctrl+J / Ctrl+K などは、下の段に出さず、`?` の一覧にだけ出す。`?` の一覧は、その窓のキーだけを出す（窓が出ている間は、リーダーに入れないため）。
4. **案内と、実際に効くキーを合わせる。** 下の段には、今効くキーだけを出す（切り替える窓は、効いている列のキー。タブをつかんでいる間は、その間のキーだけ）。下の段のキーも `?` の一覧の表のキーも、その窓のキーの判定が受けることを、テストが確かめる。
5. **字を打つ窓では、`?` は絞り込みが空の間だけ効く。** 打っている途中の `?` は、探す字として入力欄に入る。効かない間は、下の段にも出さない。日本語の変換中のキーでは、`?` も動かさない。名前の入力欄を開いている間も同じ（`?` は名前の字）。
6. **`?` の一覧を閉じると、元の所へ戻る。** 下の窓は出したままなので、選んでいた行・打ちかけの入力はそのまま残り、フォーカスは `?` を押す前にあった所（一覧か入力欄）へ戻る。
7. **`?` の一覧を出せない窓には、`?` を出さない。** kisui-terminal の外から開く履歴の小さな窓がそれで、基本操作だけを出す。
8. **マウスで閉じるボタンは、下の段のヒントの下に置く。**（今ある窓のまま。ボタンを置く・置かないは案 F）
