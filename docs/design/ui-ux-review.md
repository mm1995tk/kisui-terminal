# UI/UX の点検と共通ルール（Window の画面）

kisui-terminal の Dialog（`app/src/`）の表示と操作を、画面をまたいで点検した結果と、そこから決めた共通ルール。#306 で作った。

- 値と部品の決まりは [design-system.md](design-system.md)、キーの割り当ては [`../key-design.md`](../key-design.md) と [`../keys.md`](../keys.md)、コードの置き場は [frontend-structure.md](frontend-structure.md)。この文書は、それらをまたぐ「同じ役割のものを、同じ意味・見た目・手順にする」ための決まりと、まだそろっていない所の一覧を持つ。
- 点検の基準は main の `6b79d1a`（2026-11-19）。パスは `app/src/` からの相対。
- 画面を足す・直すときは、4 章の共通ルールに合わせる。合わせられない理由があれば、3 章の「意図した差」に足す。

## 2. 区分

3 章の各項目に、次のどれかを付ける。

| 区分           | 意味                                                                 |
| -------------- | -------------------------------------------------------------------- |
| そろえた       | 合意済みの方針で、実装までした                                       |
| コード上の差   | 同じ役割なのに、コードの上で違いがある。そろえる案は 5 章            |
| 意図した差     | 役割・入力欄の有無・壊す操作かどうか・OS の慣習から来る差。理由を残し、変えない |
| 未確定         | どちらに寄せるかを、オーナーが決める必要がある。案は 5 章            |

実行画面で見つけた不統一は、まだ無い（1 章）。見つけたら、この章の区分に「実行画面」を足して 3 章に書く。

## 3. 点検の結果

優先度は、高（同じ操作の結果や安全さが入口で変わる）・中（覚え直しが要る・意味を取り違えうる）・低（見た目だけ）。

### 3.1 ヒントとヘルプ（そろえた）

- **前の状態**：Dialog の下のヒントが Dialog ごとに違った。マシンのダイアログは 8 項目、Workspace switcher は列ごとに 9〜10 項目と、ドラッグの説明の文。ブックマークの一覧とクリップボードの履歴は、入力欄の下に「·」でつないだ 1 文。`?` で詳しい一覧が出るのは、マシンのダイアログとブックマークの一覧だけで、出る一覧はリーダーの木の全部（その Dialog が出ている間は使えない）に、その Dialog のキーを足したものだった。
- **再現する操作**：リーダー `m`・`w`・`o B`（#459 からは、ブラウザのタブでリーダー `a` → `B`）・`y`・`t m`（#454 からはリーダーに無い。設定の Shortcut の `tab.moveTo`）・`c s` で、それぞれの Dialog を開いて Key footer を見比べる。
- **利用者への影響**：同じ「選ぶ・決める・やめる」が、Dialog ごとに違う場所・違う字・違う順で出る。操作の多い Dialog ではヒントが 2〜3 行になり、基本の操作が埋もれる。
- **そろえ方**（4.7 の決まり。#487 で変えた）：#306 では、Key footer（共通フッタ）には基本操作だけを、どの Dialog でも同じ順・同じ字で出し、詳しい操作は `?` で出すとした。#487 で、Key footer に今効く操作を全部、何に効くかの見出し付きの行で出し、どの Dialog でも同じキーは出さない決まりに変えた。`?` の一覧は、その Dialog のキーだけを出す。
- **根拠**：`ui/components/KeyFooter.tsx`、`features/commands/placeKeys.ts` の `basicHints` と `placeKeys()`、`ui/main-window/commands/KeyListDialog.tsx`。
- **優先度**：中。

まだ文のままのヒント（そろえていない。5 章の案 G）：

| 所                               | 今の出し方                                         | 根拠                                             |
| -------------------------------- | -------------------------------------------------- | ------------------------------------------------ |
| ページ内検索の帯                 | 「Enter で次・Shift+Enter で前・Esc で閉じる」の 1 文 | `content/browser/FindBar.tsx` の `find.hint`     |
| 新しいタブのページ               | 検索欄の下の 1 文                                  | `content/browser/NewTabPage.tsx` の `newTab.hint` |
| リモートを足す Dialog                 | 候補を選ぶキー（`↓` `↑`・Ctrl+J / Ctrl+K）の案内が無い | `sessions/AddMachine.tsx`                        |
| キーの一覧                       | Key footer は `Esc` 閉じるのヒントだけ。表の色はパレットを直に読む | `commands/KeyListDialog.tsx`・`KeyListDialog.module.css` |
| 確認の Dialog・ssh の質問・ファイル転送 | ボタンだけ（`Enter`・`Esc` の案内は無い）           | 4.4 の決まりどおり。意図した差                   |

### 3.2 入力エラーと失敗の色（未確定）

- **現状**：
  - 名前を変えて断られた理由は、どこでも警告の色（`--state-warning`。黄）。サイドバーの帯（`sidebar.css` の `.band-rename-error`）も、その場の入力欄（`inline-input.css` の `.inline-error`）も同じ。#306 を書いた時点では、サイドバーだけ赤だった。今はそろっている。
  - Dialog のエラーの文（`card.css` の `.card-error`）も警告の色。削除できなかった・リモートを足せなかった・更新に失敗した、のような「できなかった」にも使う。
  - 内蔵ブラウザの入力欄（URL バー・新しいタブのページ・ページ内検索）は、失敗の赤（`browser.css` の `--gh-red`）。
- **再現する操作**：サイドバーでワークスペースの名前を 101 字以上にして Enter（黄）。URL バーに `ftp://example.com` を入れて Enter（赤い枠）。ページ内検索で見つからない語を打つ（赤い字）。
- **利用者への影響**：「入れた値が受け付けられなかった」が、場所によって黄と赤に分かれる。`design-system.md` は、警告を「続けられるが気をつける」、失敗を「できなかった」と決めているが、Dialog のエラーの文は「できなかった」のに警告の色。
- **案**：5 章の案 B。
- **優先度**：中。

### 3.3 閉じる・削除・切断の確認（未確定）

| 操作                         | 入口                                             | 確かめ方（今）                                            | 根拠                                                    |
| ---------------------------- | ------------------------------------------------ | --------------------------------------------------------- | ------------------------------------------------------- |
| ワークスペースを閉じる       | サイドバーの見出しの ✕                           | 聞かずに閉じる。動いているプログラムがあれば確認の Dialog      | `sidebar/workspaces/BandHeader.tsx`、`features/workspaces/controller.ts` の `closeWorkspace` |
| 同上                         | Workspace switcher の `x`・行の ✕                       | その行で `y` / `n` を聞く。その後、動いているプログラムがあれば確認の Dialog（2 回聞く） | `workspaces/WorkspaceSwitcher.tsx` の `startClose` |
| タブを閉じる                 | サイドバーの行の ✕・Workspace switcher の `x`・リーダー `t x`（#454 からは、リーダー `t` の Dialog の `x`） | 聞かずに閉じる。動いているプログラムがあれば確認の Dialog      | `features/workspaces/tabs/controller.ts` の `closeTermTab` |
| マシンを一覧から外す         | マシンのダイアログの `d`・見出しのメニュー       | 聞かずに外す（接続は切るが、マシン側の kisui serve とタブは残る） | `features/sessions/controller.ts` の `removeFromSidebar` |
| マシンを切る                 | マシンのダイアログの `x`・右下の知らせ           | 聞かずに切る（つなぎ直せる）                              | 同上の `disconnect`                                     |
| ファイル・フォルダを削除する | ファイルツリーの `d`・メニュー                   | 確認の Dialog（フォルダは「中身も消える。元に戻せない」と出す） | `sidebar/file-tree/TreeDialogs.tsx`                     |
| ブックマークを消す           | ブックマークの一覧の Ctrl+D                      | 聞かずに消す                                              | `features/browser/bookmarksStore.ts`                    |

- **再現する操作**：タブが 2 つあるワークスペースを、サイドバーの ✕ と、Workspace switcher の `x` で閉じて比べる。
- **利用者への影響**：同じワークスペースを閉じるのに、入口で確認の回数が違う。サイドバーの ✕ は、押し違いでタブをまとめて閉じる（シェルだけなら確認なし）。
- **意図した差として残すもの**：切る・外すは、つなぎ直せる・足し直せるので聞かない。ファイルの削除は元に戻せないので必ず聞く。
- **案**：5 章の案 A。誤操作を防ぐ手順を弱める変更になりうるので、合意してから直す。
- **優先度**：高。

### 3.4 フォーカス・選択・所属マシン・接続の状態（未確定）

| 所                                   | キーが向く先の見せ方                                   | 根拠                                    |
| ------------------------------------ | ------------------------------------------------------ | --------------------------------------- |
| Dialog のボタン・一覧の行                 | 青い枠 2px（`--state-focus-ring`）                     | `button.css`、`card.css`                |
| サイドバーの帯・タブの行のボタン     | マシンの色の内側 1px の枠                              | `sidebar.css` の `.band-btn:focus-visible` ほか |
| ファイルツリー・CHANGES の行         | マシンの色の内側 1px の枠                              | `tree.css`、`changes.css`               |
| 「ワークスペースを作る」・幅の広いボタン | 接続が正常の色（緑）の内側 1px の枠                 | `sidebar.css` の `.new-workspace:focus-visible`・`.band-btn-wide:focus-visible` |
| 内蔵ブラウザの入力欄                 | 青い枠 1px（パレットを直に読む）                       | `browser.css`                           |
| Workspace switcher                         | 枠は出さず、効いている列の選んでいる行の左端に色の線   | `switcher.css`                          |

- **利用者への影響**：`design-system.md` は、所属マシン・接続の状態・フォーカス・選択の 4 つを別の値で表すと決めている。サイドバーでは、フォーカスをマシンの色や接続の色で表すので、「緑の枠」が接続の状態に見えうる。
- **意図した差として残すもの**：マシンの色そのもの（どのマシンのものかを表す）。ターミナルのペインの Pane border と段の境目が、動かしている間マシンの色で光ること。
- **案**：5 章の案 C。
- **優先度**：中。

### 3.5 Pane border（つかむ所と反応）（コード上の差）

| Pane border                             | 当たり     | いつも見える印          | ポインタを乗せたとき             | 動かしている間      | 根拠                     |
| -------------------------------- | ---------- | ----------------------- | -------------------------------- | ------------------- | ------------------------ |
| ターミナルのペインどうし         | 帯の幅     | 1px の線                | マシンの色に変わり、太くなる     | マシンの色          | `terminal.css` の `.terminal-bar` |
| サイドバーと右のペイン           | 幅 4px     | 無し（ブロックの縁の線） | 変わらない（カーソルだけ）       | マシンの色          | `layout.css` の `.resizer` |
| タブの段とファイルツリーの段     | 高さ 6px   | 2px の線と真ん中の短い棒 | 変わらない（カーソルだけ）       | マシンの色          | `sidebar.css` の `.tabs-resizer` |
| ファイルツリーと CHANGES         | 高さ 6px   | 同上                    | 変わらない（カーソルだけ）       | マシンの色          | `changes.css` の `.changes-resizer` |

- **そろっている所**：段の境目 2 つは、#303 で同じ見た目（2px の線と短い棒）・同じ当たり（6px）にそろえた。動かしている間の色は 4 つとも同じ。
- **残る差**：ポインタを乗せたときに光るのは、ターミナルのペインの境目だけ。サイドバーの境目は、印も反応も無く、当たりも 4px でいちばん狭い。

- **案**：5 章の案 D。
- **優先度**：低。

### 3.6 入力に失敗したときの説明（コード上の差）

| 所                                         | 伝え方                                                        | キーボードだけで読めるか |
| ------------------------------------------ | ------------------------------------------------------------- | ------------------------ |
| その場の入力欄（名前を変える・作る）       | 入力欄の下に理由の文（`role="alert"`）。入力欄は開けたまま     | 読める                   |
| Dialog の入力（リモートを足す・削除の確認）     | Dialog の中に理由の文（`CardError`、`role="alert"`）                | 読める                   |
| ページ内検索                               | 帯の中に「見つかりません」（`role="status"`）                  | 読める                   |
| URL バー・新しいタブのページ               | 赤い枠と `aria-invalid`。理由は `title`（ポインタを乗せると出る） | **読めない**（画面に文が出ない） |
| マシンのダイアログ・キャラクターを選ぶ Dialog   | 操作できない理由を、Key footer のヒントの上に出す（`role="alert"`）   | 読める                   |

- **再現する操作**：URL バーに `ftp://example.com`（http・https でないもの）を入れて Enter。枠が赤くなるが、理由の文は出ない。
- **案**：5 章の案 E。
- **優先度**：中。

### 3.7 行の押し方と、使えない操作の伝え方（意図した差・一部は未確定）

行を 1 回押したときの動き：

| 所                                   | 1 回押す                         | 決める                               |
| ------------------------------------ | -------------------------------- | ------------------------------------ |
| サイドバーのタブの行・ファイルツリー・CHANGES | 開く（移る）              | —                                    |
| 一覧から選ぶ Dialog・マシンのダイアログ   | 選ぶだけ                         | ダブルクリックか `Enter`             |
| ブックマークの一覧・クリップボードの履歴 | 選ぶだけ（フォルダは開け閉め） | ダブルクリックか `Enter`             |
| Workspace switcher                         | 選ぶだけ                         | 選んでいる行をもう 1 回押すか `Enter` |

- **意図した差**：サイドバーとツリーは、いつも出ている「移るための一覧」で、押せばすぐ移る。Dialog は、選んでから決める（選んだ行に操作のキーが効くため）。
- **未確定**：Dialog の中で「決める」マウスの手順が 2 通りある（ダブルクリックと、選んでいる行をもう 1 回）。5 章の案 F。

使えない操作の伝え方：

| 所                               | 伝え方                               | 根拠                                         |
| -------------------------------- | ------------------------------------ | -------------------------------------------- |
| サイドバーの帯・タブの行のボタン | 出さない（場所は空けておく）         | `sidebar.css` の `.band-btn[data-off]`       |
| 見出しのメニューの項目           | 薄くして押せなくする                 | `sidebar.css` の `.machine-menu-item:disabled` |
| マシンのダイアログのキー         | 押したときに、理由を Key footer に出す     | `features/sessions/machineList.ts` の `canDo` |
| キャラクターを選ぶ Dialog の行         | 行に「使えません」、決めようとすると理由 | `mascot/MascotDialog.tsx`                 |
| Dialog のボタン                       | 薄くして押せなくする（`disabled`）   | `button.css`                                 |

- **意図した差**：行のボタンは場所が狭く、理由を出せないので出さない。キーの操作は「押せるかどうか」を先に見せられないので、押したときに理由を出す。
- **優先度**：低。

### 3.8 同じ名前を変える操作のキー（未確定・キーの変更は未合意）

| 所                             | 名前を変える | そのキーのほかの意味（同じ所）       |
| ------------------------------ | ------------ | ------------------------------------ |
| マシンのダイアログ             | `n`          | `r` はつなぎ直す                     |
| Workspace switcher（ワークスペース・タブ） | `r`    | `n` は作る                           |
| ファイルツリー                 | `r`          | `n` はファイルを作る                 |
| リーダー                       | `t r`（タブ）・`o R`（ブラウザのタブ）（#454・#459 からは、どちらもリーダー `t` の Dialog の `r`） | —              |

- **利用者への影響**：名前を変えるのは 4 か所のうち 3 か所で `r`。マシンのダイアログだけ `n` で、そこでは `r` がつなぎ直す。Workspace switcher の `n`（作る）に慣れた手でマシンのダイアログの `n` を押すと、名前の入力欄が開く（壊す操作ではない）。
- **今の補い方**：どの Dialog でも `?` でその Dialog のキーの一覧が出る（3.1）。
- **案**：5 章の案 H。キーを変えるので、合意してから。
- **優先度**：中。

### 3.9 Dialog の閉じ方（コード上の差）

- `Esc` で閉じる Dialog には、閉じるだけの「閉じる」「やめる」ボタンも ✕ も置かない（`design-system.md`。クリップボードの履歴は、真ん中の Dialog も外から開く小さな Window も同じ）。閉じ方は、どの Dialog でも `Esc`（4.7 の決まり 3 で、Key footer には出さない。まだ前の決まりの Dialog（クリップボードの履歴・DB の履歴・DB の権限を強める Dialog）は、Key footer に `Esc` を出す）。
- Window の外を押して閉じるのは、Workspace switcher だけ（`closeOnOutside`）。一覧から選ぶ Dialog・マシンのダイアログ・ブックマークの一覧は、打ちかけの入力が無いのに閉じない。
- マウスで閉じる手段：Workspace switcher は外を押す。ほかの Dialog は無い（`Esc` だけ。決める・許す・送る Dialog のボタンと、それとやめるを選ぶ確認の Dialog の「やめる」は別）。
- **案**：5 章の案 F。
- **優先度**：中（Window の外を押して閉じるかは、案 F の残り）。

## 4. 共通ルール

「決まり」は、今の実装が従っているもの。新しく作る所も従う。「未確定」は 5 章の案が決まるまで、今のままにする。

### 4.1 色と状態

- 決まり：色は役割の名前（`tokens.css`）で選ぶ。状態は `design-system.md` の「状態」の表の意味で使う。
- 決まり：名前の入力が断られた理由は、どこでも同じ色（今は警告の色）・同じ場所（入力欄のすぐ下）に出す。
- 未確定：「入れた値が受け付けられなかった」と「操作ができなかった」を、警告の色にするか失敗の色にするか（案 B）。

### 4.2 フォーカスと選択

- 決まり：所属マシン・接続の状態・フォーカス・選択は別の意味で、新しく作る所では別の値で表す（`design-system.md`）。
- 決まり：Dialog の一覧は、選んでいる行を 1 つ持ち、キーはその行に効く。フォーカスは一覧（か入力欄）に置いたままにし、行には移さない（`aria-activedescendant`）。
- 未確定：サイドバー・ファイルツリー・CHANGES の Focus frame の色（案 C）。

### 4.3 ボタンと入力

- 決まり：Dialog のボタンは `Button`。主の操作は 1 つで右端。やめる・閉じるは左（`design-system.md`）。
- 決まり：名前を変える・作るは、Dialog を出さず、その行をその場の入力欄にする（`InlineInput`）。
- 決まり：入力が断られたら、入力欄を開けたまま、理由を文で出す（色だけ・`title` だけで伝えない）。URL バーと新しいタブのページは、まだ従っていない（案 E）。

### 4.4 確定と取り消し

- 決まり：`Enter` は決める、`Esc` はやめる（閉じる）。日本語の変換を確定する `Enter` と、変換をやめる `Esc` では動かさない（`isComposingKey`）。
- 決まり：`Esc` は、いちばん内側のものだけをやめる。その場の入力欄 → 行の中の確認（`y` / `n`）・つかんだタブ → Dialog、の順。Dialog の `?` の一覧を `Esc` で閉じても、下の Dialog は閉じない。
- 決まり：確認の Dialog（閉じる・入れる・許す・削除）と、入力して送る Dialog（ssh の質問・リモートを足す）は、ボタンが案内を兼ねる（主ボタンが `Enter`、「やめる」が `Esc`）。Key footer にキーのヒントは出さない。
- 決まり：ユーザーの操作と関係なく開く Dialog は、フォーカスを Dialog そのものに置き、打っていた `Enter` がボタンを押さないようにする（`focusSelf`）。

### 4.5 閉じる・削除・切断

- 決まり：元に戻せない操作（ファイルの削除）は、必ず確認の Dialog で聞く。
- 決まり：動いているプログラムがあるターミナルを閉じるときは、入口によらず確認の Dialog で聞く。
- 決まり：戻せる操作（切る・一覧から外す・ブックマークを消す）は聞かない。
- 未確定：ワークスペースを閉じる前に、プログラムが動いていなくても聞くか（案 A）。

### 4.6 Pane border

- 決まり：動かしている Pane border（ドラッグ中・リサイズモードで選んでいる間）は、マシンの色で光らせる。
- 決まり：段の境目は、2px の線と真ん中の短い棒（#303）。
- 未確定：ポインタを乗せたときの反応と、サイドバーの境目の印（案 D）。

### 4.7 ヒントとヘルプ

Dialog（真ん中に出す `ModalCard`）のうち、キーで一覧を動かすものが対象。キーを覚えなくても、次に何ができるかが Key footer で分かるようにする（#487。それまでは、Key footer に基本操作だけを出し、詳しい操作は `?` の一覧に任せていた）。

1. **今効く操作は、全部 Key footer（共通フッタ）に出す。** Key footer に出すのは、その Dialog だけの操作のうち、今効くもの。効かない操作は出さない（理由も出さない）。選んでいる行・効いている列・Dialog の状態（名前を打っている・確かめている・つかんでいるなど）が変わると、中身が変わる。右に列を足したり、Dialog を大きくしたりはしない。
2. **何に効くかで行を分け、行の頭に見出しを付ける。** 例：DB のタブの Dialog は「選んでいるタブ」と「この DB のタブ」の 2 行。見出しは説明の文なので、日本語の Dialog では日本語。行の中の操作の名前（`rename`・`close` など）は、ほかの操作の名前と同じく、日本語の Dialog でも英語（AGENTS.md の「UI strings of the window」。i18n のキーは `<Dialog>.keys.<名前>`、見出しは `<Dialog>.foot.<名前>`）。
3. **どの Dialog でも同じ意味のキーは出さない。** 選ぶ `j` `k`・列を移る `h` `l`・矢印・決める `Enter`・やめる／閉じる `Esc`・`?`・Ctrl+J / Ctrl+K（`features/commands/placeKeys.ts` の `COMMON_KEYS`）。例外は、キーの意味が変わる間だけ出す（マシンのダイアログの `Enter`＝選んだマシンでターミナルのタブを作り始める（選ぶ Dialog の「決める」ではなく、この Dialog だけの操作）、Workspace switcher でタブをつかんでいる間の `j` `k` `h` `l` `Enter` `Esc`、作るタブの種類を選ぶ間の `Esc`、ターミナルのタブを作る欄でマシンの一覧を開く `↓`）。同じ字が、その Dialog では別の操作のとき（DB のタブの Dialog の `h` は履歴）も出す。
4. **`?` の一覧への案内は、Key footer に出さない。** `?` の一覧（`KeyListDialog`）は残す。役割は、その Dialog のキーの全部の表：今は効かない操作、どの Dialog でも同じキー、同じ操作の別のキー（矢印・Ctrl+J / Ctrl+K・`g` `G`）を含めて、1 か所で見る所。Key footer で足りるので、案内はしない（`?` を押せば出る）。`?` の一覧は、その Dialog のキーだけを出す（Dialog が出ている間は、リーダーに入れないため）。
5. **Key footer はいつも出す（出たり消えたりしない）。** Dialog だけの操作が無い間（名前を打っている間・結果のタブが無い間の「選んでいるタブ」の行など）は、行の見出しだけを出す。
6. **選ぶ間の選択肢は、Key footer の押せるボタンにする。** Workspace switcher で作るタブの種類を選ぶ間は、右の列に一覧を出さず、Key footer に `t`・`b`・`B`・`d` のボタンを出す。字を押しても、ボタンを押しても決まる（選ぶ行は無いので、`j` `k`・`Enter` では選ばない）。
7. **案内と、実際に効くキーを合わせる。** Key footer の項目は、`?` の一覧の表（`placeKeys()`）の行から作る（`placeItem`。出すキーと、判定に通すキーを表から引く）。表に無い状態のキー（つかんでいる間など）は、その状態の判定に通すキーを項目に書く。テストが、Key footer に出す項目を、その状態の Dialog の判定が受けることと、表の操作が（どの Dialog でも同じキーを除き）どれも、どこかの状態で Key footer に出ることを確かめる。
8. **字を打つ Dialog では、`?` は絞り込みが空の間だけ効く。** 打っている途中の `?` は、探す字として入力欄に入る。日本語の変換中のキーでは、`?` も動かさない。名前の入力欄を開いている間も同じ（`?` は名前の字）。
9. **`?` の一覧を閉じると、元の所へ戻る。** 下の Dialog は出したままなので、選んでいた行・打ちかけの入力はそのまま残り、フォーカスは `?` を押す前にあった所（一覧か入力欄）へ戻る。
10. **`Esc` で閉じる Dialog に、閉じるだけ・やめるだけのボタンは置かない。** 閉じ方は、どの Dialog でも `Esc`。ボタンを置くのは、決める・許す・送る操作と、それとやめるを選ぶ確認の Dialog だけ。

11. **選ぶだけの小さな Dialog は、見出しだけを出す**（#489）。操作が選ぶ・決める・やめるだけの Dialog（マシン・移す先のワークスペース・ワークスペースの種類・キャラクター・DB の接続・DB の書き出しの形を選ぶ Dialog）には、Dialog だけの操作が無い（`j` `k`・`g` `G`・Ctrl+J / Ctrl+K・`Enter`・`Esc`・`?` は、どの Dialog でも同じキー）。決まり 3 と 5 から、Key footer は、何を選ぶかの見出しだけの 1 行（`pickOnlyRows`）。選ぶキーと決めるキーの案内は出さない（`?` の一覧の表 `picker` に全部ある）。選ぶ Dialog の表に、どの Dialog でも同じキー・その別のキー以外が増えたら、見出しだけでは足りないので、テスト（`placeKeys.test.ts`）が落ちる。

まだこの形にしていない Dialog（クリップボードの履歴・DB の履歴・DB の権限を強める Dialog）は、前の決まり（Key footer に基本操作「選ぶ → 移る → 決める → `?` → やめる・閉じる」を、`placeKeys.ts` の `basicHints` で出し、詳しい操作は `?` の一覧に出す）のまま。`basicHints` と `KeyFooter` の `items` は、使う Dialog が無くなったら消す。

Key footer と `?`（4.7）：

1. リーダー `m`。Key footer が「`j` `k` 選ぶ・`?` キーの一覧・`Esc` 閉じる」だけ（閉じるボタンは無い）。2 行目のマシンを選び、`?`。マシンのダイアログのキーだけの一覧が出て、その Key footer には `Esc` 閉じるのヒントだけがある（閉じるボタンは無い）。`Esc`。一覧だけが閉じ、2 行目が選ばれたまま、`j` `k` が効く。
2. リーダー `w`。Key footer が「ワークスペース」と「この Dialog」の 2 行で、`Enter`・`Esc`・`j` `k`・`?` は出ない。`l` でタブの列へ。Key footer が「タブ」の 1 行（`r` `x` `J` `K` `m` `n`）に替わる。`?`。タブの列のキー、ワークスペースの列のキーの順に出る。`Esc` のあと、選んでいたタブのまま。`n`（タブの列）で、Key footer が「作るタブ」の行になり、`t` `b` `B` `d` のボタンと `Esc` が出る。ボタンを押しても、字を押しても決まる。右の列に一覧は出ない。
3. Workspace switcher で `r`（名前の入力欄）。Key footer が「名前を入力中」の見出しだけになる（消えない）。`?` を打つと、名前に `?` の字が入る（一覧は出ない）。`Esc` で入力をやめる。
4. Workspace switcher のタブの列で `m`。Key footer が「タブを移す」の行（`j` `k` where・`h` `l` column・`Enter` drop・`Esc` put back）になり、`?` は何もしない。
4a. リーダーの `a`（DB のタブを出しているとき）。Key footer が「選んでいるタブ」と「この DB のタブ」の 2 行。結果のタブが無いときは 1 行目が見出しだけで、SQL を実行すると `x` などが出る。実行中だけ `c` が、権限を強めている間だけ `P` が出る。
5. リーダー `c s`、設定の Shortcut の `tab.moveTo`（タブを移す先を選ぶ Dialog）、サイドバーの帯の「+」のメニューの、マシンを選ぶターミナル（つながっているマシンが 2 つ以上のとき）。どれも Key footer が「選ぶ・（Enter の字）・キーの一覧・やめる」で、`?` で「一覧から選ぶ Dialog」のキーが出る。
6. ブラウザのタブでリーダー `a` → `B`。Key footer に `?` が出ている。字を 1 つ打つと、Key footer から `?` が消え、`?` を打つと入力欄に入る。字を消すと `?` が戻り、`?` でブックマークの一覧のキーが出る。`Esc` のあと、入力欄にフォーカスが戻る。
7. リーダー `y`。入力欄の下にあった 1 文が無くなり、Key footer に「`↓` `↑` 選ぶ・`Enter` 貼る・`?`・`Esc` 閉じる」。Shift+Enter で、Key footer が「コピーしました」に替わってから閉じる。履歴が空のときも、Key footer が出る。
8. Option+Space（Linux は Alt+Space）で外から開く履歴。Key footer が Window の下の端にあり、`?` は出ない。履歴が空でも下の端にある。
9. 日本語の入力（かな漢字変換）を入にして、ブックマークの一覧（ブラウザのタブでリーダー `a` → `B`）とクリップボードの履歴（リーダー `y`）で「？」を打つ。変換中は一覧が出ない。
10. ウィンドウの幅を 700px ほどに縮め、表示の大きさを上げ（Cmd+= / リーダー `v +`）、`ui-language = "en"` と `"ja"` の両方で、1〜7 の Key footer が、項目の途中で切れずに折り返すこと。

3 章のほかの項目は、各項目の「再現する操作」で見る。
