## 2. 方針

1. **操作はリーダーの木に置く。** 場所のキー（5 章）を除き、操作には、リーダーの木（Mac は Cmd+K、Linux は Ctrl+Shift+K）の下にキーを付ける。リーダーの木は kisui-terminal だけのキーの場所で、ターミナルの中のプログラム（シェル・shj）のキーとぶつからないので、置くときにぶつかりを調べる手間が小さい。画面の中の場所を指す操作（境界のドラッグ、ターミナルの URL のクリック、OS からのファイルのドロップなど）は、理由を書かずに GUI だけの操作にしてよい（6.2 の表には、キーの無い操作として載せる）。それ以外の操作を GUI だけにするときは、理由を表に書く。
2. **shj と役割を分ける。** shj の `Space` は、エディタとその周り（ファイルツリー・変更一覧・分割・プレビュー）の操作を受け持つ。kisui のリーダーは、kisui にしかない操作（ワークスペース・マシン・ペイン・サイドバーの開け閉め・表示の大きさ・お知らせ・クリップボードの履歴・内蔵ブラウザのタブ）だけを受け持つ。同じ操作を両方に持たない。ファイルツリーと変更一覧はプライマリのペインの shj があるときだけ出るので、そこへ移るのは shj の `Space e` `Space g` に任せる。
3. **shj のキーを奪わない。** ターミナルにフォーカスがあるとき、kisui が受けるのは、Mac は Cmd を含むキー、Linux は Ctrl+Shift+字だけ。Linux では Super・Ctrl 単独・Alt 単独のキーを新しく使わない。例外は、何も奪わない今の Ctrl+`=` `0`（4.2）、アプリの外のキー（Option+Space / Alt+Space）、ダイアログが出ている間だけ効く Ctrl+J / Ctrl+K（5 章）、内蔵ブラウザを表示している間だけ効く Ctrl+F（ページ内検索。5 章。#205）。旧来の端末の符号では Ctrl+Shift+字は Ctrl+字と同じで、kisui は Shift 付きだけを取るので、Ctrl+字は shj やシェルに届く。矢印は別で、Ctrl+Shift+矢印は Ctrl+矢印と別の符号になり shj が使うので、取らない（8 章）。ターミナルにフォーカスが無いとき（内蔵ブラウザのページ、ファイルツリー、CHANGES など）は、シェルや shj にキーが届かないので、これらのキーとのぶつかりを気にせずに近道を置いてよい。たとえば、内蔵ブラウザを表示している間だけ、Cmd+R を読み込み直しに、Cmd+F / Ctrl+F をページ内検索にする。そのキーは、その場所の中だけで効き、その場所の `?` の一覧に載せる（5 章）。
4. **ホームポジションから手を離させない。** 新しいキーに矢印・PageUp・PageDown を使わない。向きと順送りは vim の流儀の `h` `j` `k` `l`（`j` が次・下、`k` が前・上、`h` `l` が左右や一段大きい単位の前後）、直前の場所との行き来は `Tab`。Emacs の流儀（Ctrl+N・Ctrl+P）は混ぜない。今ある矢印のキー（ダイアログ・動画）は、`h` `j` `k` `l` と並べて残す。
5. **リーダーを入り口にする。** 操作は次の層で持つ。
   - **リーダー**：Mac は Cmd+K、Linux は Ctrl+Shift+K。押すと、次に押せるキーの一覧（リーダーの一覧）が出る。場所のキーとアプリの外のキー（Option+Space）を除く、すべての操作がここの下にある。覚えなくても使える層。
   - **窓の入口の近道**：リーダーから開く窓を 1 回で開くキー（ワークスペースの窓の Cmd+Shift+W / Ctrl+Shift+W だけ）。字はリーダーの中と同じで、Mac は Cmd+Shift、Linux は Ctrl+Shift を付ける（4.1）。リーダーのグループに 1 回で入る近道は、#457 で無くした。
   - **近道**：既定のものは少なく保つ（今あって何も奪わない近道だけを残す。4.2）。リーダーの下にも同じ操作がある。よく使う操作の近道は、ユーザーが設定ファイルで足せる（4.3）。
   - **場所のキー**：ファイルツリー・変更一覧・動画・画像・リサイズモード・ダイアログの中で、そこにフォーカスがあるときだけ効くキー。リーダーには載せず、その場所の `?` の一覧に載せる。
6. **近道は 1 つの操作に OS ごとに 1 つ。** 別名で同じ操作を二重に持たない。Mac の Cmd（と Cmd+Shift）のキーは、Linux では Ctrl+Shift のキーにする。Mac で Cmd+Shift を使うキーも、Linux では Ctrl+Shift（Shift を二重にはしない）。
7. **リーダーの一覧の葉は、名前の付いたコマンドを呼ぶ。** キーとリーダーの一覧は、コマンドの表（コマンドの名前・キー・説明）という 1 つの定義から作る。案内とずれないようにし、キーを変えるときも 1 か所を直せば済むようにするため（#92 で実装）。`kisui` のコマンドから呼べるようにすることは、今はしない。

## 3. リーダー

### 3.1 入るキーと動き

| OS    | キー         | 注意                                                                                                                                                        |
| ----- | ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Mac   | Cmd+K        | Mac の OS・WebView・ターミナルのプログラムは Cmd+K を受けない。                                                                                             |
| Linux | Ctrl+Shift+K | Shift なしの Ctrl+K は、shj（コマンドパレット）とシェルに届く。Super+K と違い、Windows（Win+K は OS のキャスト）や i3・sway でもウィンドウマネージャーに取られない。 |

動き：

- 押すと、画面の右下にリーダーの一覧（案内）を出す。ターミナルの文字は左に寄るので、右下のほうが入力中の行に重なりにくい（shj の Space の案内も右下）。右下のお知らせのカードにも重なるので、案内のほうを手前に置く（押せない表示なので、案内を出している間、重なった部分のカードのボタンは押せない）。キーが向く先は、押した瞬間にフォーカスがあったペインのまま変わらない。
- 次のキーで、動きを行う（葉）か、一段下の一覧に入る（グループ）。キーは、1 つの一覧の中で重ならない。
- `Esc` はリーダーを出る。`Backspace` は一段戻る（一番上では出る）。リーダーのキーをもう 1 度押しても出る。
- 一覧に無いキーを押したら、そのキーは捨てて（シェルや shj には送らない）、リーダーを出る。誤って文字がシェルに入るのを避けるため。
- **続けて押せる葉**：3.2 の表で「続けて」と書いた葉は、行ったあともリーダーを出ず、同じ一覧のまま次のキーを待つ。ペインを `j` `j` `l` と続けて移れる。ほかのキーを押すと、上の決まりどおり、そのキーを捨てて出る。
- 時間で閉じない（押し直しを強いない。shj の Space の案内と同じ）。
- 入るときの条件：かな漢字変換中（`isComposing`）は受けない。ダイアログが出ている間は受けない（ダイアログの `Esc` が先）。それ以外はどこにフォーカスがあっても効く（ファイルツリー・変更一覧・動画・画像の中でも）。リサイズモードの中では、リーダーに入らず、リサイズモードのキーを優先する。
- リーダーの一覧と、実際に受けるキーは、コマンドの表から作る（2 章の方針 7。#92 で実装）。
- 案内の文は短くする（「左のペインへ」「ペインを閉じる」など。括弧書きの補足は書かない）。補足は、この表の「動き」と `keys.md` に残す。ただし、案内の文と `?` の一覧の文は同じ表（`features/commands/commands.ts` の `LEADER`）から作るので、同じ短い文になる。
- 案内で、Mac は `v`（表示の大きさ）のグループを出さない（Cmd+= / Cmd+- / Cmd+0 が共通の操作なので、案内に頼らない）。Linux は出す（Ctrl+- は端末の Ctrl+_ と同じ信号なので近道が無く、`v -` しか小さくするキーが無い）。`?` の一覧は、どの OS でも全部出す。
- 案内で、向きの `h` `j` `k` `l` は、同じ操作の向き違いなので 1 行にまとめる（`h|j|k|l  ペインを移動`。DB の結果のページ送り `j|k` も同じ）。キーの割り当てと動きは変えない。`?` の一覧も同じ表から同じ範囲（`range`）でまとめる（まとめた行に設定で近道を足すと、`Alt+J (j)` のように、どのキーのものかを添える。キーを押したときの動きは葉ごと）。一覧の説明文と 3 列の見出しは固定し、下の行だけをスクロールする。

- ブラウザのタブ・DB のタブを出している間のペインの操作（`h` `j` `k` `l`・`Tab` と、ペインの近道・設定の近道）は、まずグリッドに戻してから行う（見えないペインを動かさない）。ペインを閉じる（Cmd+W・設定の近道の `pane.close`）は、グリッドに戻すだけで閉じない（どのペインが閉じるか見えないまま閉じないため）。Cmd+W は、ページにキーがあっても、窓も閉じない。

### 3.3 場所のキーでも `?`

ファイルツリー・変更一覧・動画・画像のペインにフォーカスがあるとき、`?` でその場所のキーの一覧を出す。リーダーの `?`（全部のキーの一覧）も、今フォーカスがある場所があれば、その場所のキーを先に出す（#115）。リサイズモードは、入っている間、使えるキーを画面に出す（#92）。

窓（ダイアログ）のうち、キーで一覧を動かすもの（マシンのダイアログ・ワークスペースを切り替える窓・ターミナルのタブの窓・DB のタブの窓・ブラウザのタブの窓・一覧から選ぶ窓・ブックマークの一覧・クリップボードの履歴）は、`?` でその窓のキーの一覧を出す（#306）。下の段には、ワークスペースを切り替える窓と DB のタブの窓は、今効く操作を全部、何に効くかの見出し付きの行で出し（どの窓でも同じキーと `?` の案内は出さない。#487）、ほかの窓は基本操作（選ぶ・移る・決める・`?`・やめる／閉じる）だけを出す（#488・#489 で、今効く操作を出す形にする）。窓が出ている間はリーダーに入れないので、この一覧にはリーダーの木を出さず、その窓のキーだけを出す。一覧を `Esc` で閉じると、下の窓の、選んでいた行・打ちかけの入力・フォーカスに戻る。字を打つ窓（ブックマークの一覧・クリップボードの履歴）では、`?` は絞り込みが空の間だけ効く（打っている途中の `?` は探す字）。名前の入力欄を開いている間と、切り替える窓でタブをつかんでいる間・閉じる確認の間・作るタブの種類を選ぶ間・ターミナルのタブの窓で分ける向きを待っている間は、`?` は一覧を出さない。決まりは `docs/design/ui-ux-review.md` の 4.7。

## 4. 近道（リーダーを通さずに 1 回で押せるキー）

### 4.3 ユーザーが設定ファイルで足す近道（#199）

既定の近道を少なく保つ代わりに、よく使う操作は、ユーザーが自分で 1 回で押せるようにできる。どのキーが、自分の使うプログラム（シェル・shj・vim・tmux など）とぶつかるかを一番知っているのはユーザーなので、方針 3 のキーの縛りは、設定で足すキーには掛けない（ただし 1 つ縛る。下の「修飾キー」）。

設定ファイル（`$XDG_CONFIG_HOME/kisui-terminal/config.toml`、上に重ねる `config.local.toml`）の `[gui.shortcuts]` に、`"キー" = "コマンドの名前"` を書く。

```toml
[gui.shortcuts]
"Ctrl+Alt+N" = "workspace.new"
"Alt+J" = "pane.focus:down"
"Cmd+Shift+D" = "none" # 既定の近道を消す
```

- **キーの書き方**は、この文書の表と同じ（`Cmd`・`Ctrl`・`Shift`・`Alt`（Option）を `+` でつなぎ、最後に 1 つのキー。1 文字（字・数字・記号）か、Enter・Tab・Escape・Backspace・Space・矢印（Left・Right・Up・Down）・F1〜F12。ほかの名前は間違い）。修飾キーとキーの名前の大文字小文字は問わず、`Command`・`Control`・`Option` も使える。このマシンの OS で押すキーをそのまま書く（Mac と Linux の書き分けは要らない。設定のフォルダはマシンごと）。
- **修飾キー**：`Cmd`・`Ctrl`・`Alt` のどれかを含める。字だけ（Shift だけ）のキーは、ターミナルで打てなくなるので受けない。
- **コマンドの名前**は `app/src/features/commands/commands.ts` の動きの名前（正は `features/commands/commands.ts` の表。名前を足したらここも直す）で、引数があるものは `名前:引数` と書く。リーダーの木の葉と同じ動きに、木に載せないワークスペースのコマンド（`features/commands/commands.ts` の `SHORTCUT_ONLY`。#296。下の - **2 つのファイル**：キーごとに重ね、同じキーは `config.local.toml` が勝つ。
- **間違い**（読めないキー・知らないコマンド・リーダーのキーと同じ・同じキーを 2 回書いた・修飾キーが無い）は、起動を止めず、右下のお知らせに理由を出し、その近道だけ使わない。値が文字列でないなど TOML の型の間違いは、ほかの設定と同じく、場所と理由を出して起動しない。
- **`?` の一覧**：足した近道は、そのコマンドの最初の行の「近道」の欄に（既定の近道があれば並べて）出る。リーダーの木に無いコマンドに足した近道は、木のあとの「Shortcuts only」の行に、既定の近道だけを持つ操作（ペインを分ける Cmd+D など）と一緒に並ぶ（#457）。内蔵ブラウザのページにキーがある間も効く（既定の近道と同じ）。
- リーダーの木のキーは変えない。既定の近道（4.1・4.2）は、同じキーを書けば上書きでき、`none` で消せる。リーダーのキー自身は変えられない（間違いになる）。

## 8. shj・ターミナルの中のプログラムのキーを奪わないか

kisui-terminal は、キーをペインに届く前（`window` の `keydown` の capture）で受ける。GUI のキーに当たったキーは、シェルにも shj にも送らない。そこで、この表のキーが、shj（[shijimi-editor の README](https://github.com/mm1995tk/shijimi-editor) の「Keys」の章）と、ターミナルの中の一般のプログラムのキーと重ならないかを調べた。

### 8.1 shj のキーとの照合

shj が受けるキー（README の Space メニュー・Helix モード・VS Code モード・ターミナルパネル・検索パネル）：`Space` で始まる操作（`Space f/b/w/e/k/o/r/s/d/g/G/x/m/v/y/p/?` など）、`F1`、`Ctrl+K`、`Ctrl+P`、`Ctrl+B`、`Ctrl+E`、`Ctrl+G`、``Ctrl+` ``、`Ctrl+J`、`Ctrl+S`、`Ctrl+W`、`Ctrl+Tab`、`Ctrl+\`、`Ctrl+1` / `Ctrl+2`、`Ctrl+Q`、`Alt+R`、`Alt+A`、`Alt+I`、`Alt+C`、`Alt+←` `Alt+→`、`Ctrl+Alt+D` / `Ctrl+Alt+U`、`Ctrl+O` / `Ctrl+I`、`Ctrl+C`、`Ctrl+X`、`Ctrl+Z`、`Ctrl+F`、`Ctrl+Shift+←` `Ctrl+Shift+→` `Ctrl+Shift+Home` `Ctrl+Shift+End`（選択）、`Ctrl+Shift+Z`（やり直し）、`Ctrl+_` / `Ctrl+/`（コメントの切り替え）ほか。shj は Cmd・Super を使わない。

| kisui のキー                                                                                       | shj のキーとの関係                                                                                                                                                                                       | 結論     |
| -------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| リーダー Cmd+K（Mac）                                                                              | shj の `Ctrl+K`（コマンドパレット）とは別のキー。Cmd は shj に届くキーではない。リーダーの中の字は、リーダーが受けるので shj には届かない。shj の `Space` のメニューとは入り口が別。                    | 奪わない |
| リーダー Ctrl+Shift+K（Linux）                                                                     | 旧来の端末の符号では Ctrl+K と同じ。kisui は Shift 付きだけを取り、Shift なしの Ctrl+K は shj に届く。shj の Ctrl+Shift+字は、やり直しの Ctrl+Shift+Z だけ。                                              | 奪わない |
| Cmd+Shift+W（Mac）・Ctrl+Shift+W（Linux）（ワークスペースの窓を開く。#457 までは、P でペインのグループに入った。今は P を取らないので、Cmd+Shift+P / Ctrl+Shift+P はターミナルに届く）                                       | Mac は Cmd なので届かない。Linux は Shift 付きだけを取り、shj の `Ctrl+W`（ファイルを閉じる）は届く。                                                                                         | 奪わない |
| Cmd+D / Cmd+Shift+D / Cmd+W / Cmd+R / Cmd+Shift+H / Cmd+Shift+Enter / Cmd+= - 0（Mac）   | Cmd のキーは shj に届かない。                                                                                                                                                                            | 奪わない |
| Ctrl+Shift+D / E / H / M / R（Linux）                                                              | shj は Ctrl+Shift+D / E / H / M / R を使っていない（shijimi-editor の `core/app.go` で確かめた）。                                                                                                       | 奪わない |
| Linux の Ctrl+`=` `0`                                                                              | shj は使っていない。                                                                                                                                                                                     | 奪わない |
| ブラウザのタブの窓（リーダーの `a`。内蔵ブラウザ。#459 までは `o` のグループ）                     | リーダーの中の字なので、shj には届かない。                                                                                                                                                               | 奪わない |
| リーダーの `t`（ワークスペースの窓を開く）                                                                | リーダーの中の字なので、shj には届かない。                                                                                                                                                               | 奪わない |
| ダイアログの一覧の Ctrl+J / Ctrl+K                                                                 | ダイアログが出ている間だけ受ける。キーはダイアログに届き、ターミナルには届かない。                                                                                                                      | 奪わない |
| （消す）Linux の Ctrl+`-`                                                                          | 端末の `C-_` と同じ符号で、shj のコメントの切り替え（`ctrl+_`）を奪っていた。消すので、届くようになる。                                                                                                  | —        |
| （消す）Ctrl+Shift+←/→（Linux の「隣のペインへ移る」と Mac の別名）                                | shj の単語単位の選択（`ctrl+shift+left` / `ctrl+shift+right`）を奪っていた。Ctrl+Shift+矢印は旧来の端末でも Ctrl+矢印と別の符号（`CSI 1;6D` など）になるので、shj に届くキー。消すので、届くようになる。 | —        |

場所のキー（修飾キー無しの `m` `c` `.` `?`・画像の `+` `-` `0`）は、ファイルツリー・変更一覧・画像のペインにフォーカスがあるときだけ効く。そのときのフォーカスは kisui の部品にあり、shj のキーを受けるターミナルのペインにはないので、shj には影響しない。ただし変更一覧は、`s` `r` `R` `:` `Space` を shj に渡す（`keys.md` の 1.4）。ここに足す `?` は、今変更一覧から shj に渡している字に無いので、kisui が受けても shj のキーは減らない。

### 8.2 ターミナルの中のプログラムのキーとの照合

| キー                                                                        | 奪うもの                                                                                                                                                                                                                         |
| --------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Mac の Cmd 系すべて                                                         | 何も奪わない（Cmd は端末の符号にならない）。                                                                                                                                                                                     |
| Linux の Ctrl+Shift+字（D・E・H・K・M・P・R・W）。矢印は含まない           | 旧来の端末の符号では Ctrl+字と同じで、区別して受けるプログラムはほぼ無い。kisui が取るのは Shift 付きだけで、Ctrl+字は届く。kitty のキーボード拡張を使うプログラムが Ctrl+Shift+字を割り当てていると、届かない（今も同じ）。 |
| Linux の Ctrl+`=` `0`                                                       | 何も奪わない。                                                                                                                                                                                                                   |
| Option+Space・Alt+Space（アプリの外からの履歴のダイアログ）                 | OS 全体のキー。Alt+Space は、ウィンドウマネージャーがウィンドウメニューに使うことが多く、取れない環境がある（今も同じ）。                                                                                                        |
| 内蔵ブラウザのページの中のキー                                              | ページにキーがある間、kisui が受けるのはリーダーと近道だけ（ターミナルと同じキー）。ほかのキー（字・`?`・Cmd+C / Cmd+V など）はページに届く。Cmd+R / Ctrl+Shift+R は、ブラウザを出している間は読み込み直しになる（ページ自身の Cmd+R と同じ動き）。Cmd+F / Ctrl+F は、ブラウザを出している間はページ内検索になり、ページ自身の Cmd+F / Ctrl+F には届かない（#205）。 |
| リーダーの中のキー                                                          | リーダーに入っている間だけ受ける。リーダーに入るのは、リーダーのキーを押したときだけなので、シェルや shj のキーを奪わない。                                                                                                      |

Linux では Super を使わないので、Super のキーをウィンドウマネージャーや OS が先に取る環境（i3・sway・Hyprland、Windows の Win+K など）でも、すべてのキーが届く。

## 9. 決めるときに比べた候補と、選んだ案

PR #106 で、次の 9 つを比べて選んだ。決めるときに先に置いた原則は 2 章（shj と役割を分ける・shj のキーを奪わない・矢印を使わない・リーダーを入り口にして近道は最小）。

1. **Linux・Windows のリーダーのキー**：A. Super+K だけ / B. Super+K と Ctrl+Shift+K の両方 / **C. Ctrl+Shift+K だけ（選んだ）**。Super+K は Windows と i3・sway で届かない。Linux の kisui のキーをすべて Ctrl+Shift+字にそろえられる。
2. **Linux の表示を小さくするキー Ctrl+`-`（shj のコメントの切り替えとシェルの undo を奪う）**：A. 今のまま / **B. リーダー `v` だけにする（選んだ）**。ただし、何も奪わない Ctrl+`=` と Ctrl+`0` は近道として残す。
3. **Linux のワークスペースを番号で選ぶ近道**：**A. 置かない（選んだ。#296 までは、リーダー `w 1`〜`w 9`。今は窓で選ぶ）** / B. Ctrl+Alt+1〜9 / C. Alt+1〜9。
4. **ワークスペースを移る近道**：A. #88 の案（Ctrl+Cmd / Ctrl+Super + h/j/k/l） / B. Cmd+Shift+] / [・Ctrl+PageDown / PageUp / **C. 近道なし、リーダーだけ（選んだ）**。使う回数が多くないため。代わりに、ワークスペースのグループに 1 回で入る近道（Cmd+Shift+W / Ctrl+Shift+W）を足した（#296 で、ワークスペースの操作を窓に集め、この近道は窓を開く近道になった）。B は PageUp・PageDown を使うので、方針 4 にも合わない。
5. **ワークスペースを作る近道**：**A. 置かない（選んだ）** / B. Cmd+T・Ctrl+Shift+T。
6. **Linux の「分けたペインを閉じる」近道**：A. Ctrl+Shift+W を足す / **B. リーダーだけ（選んだ）**。Ctrl+Shift+W は、ワークスペースの窓を開く近道に使う（#296 までは、ワークスペースのグループの入口）。
7. **Mac の別名（Ctrl+Shift+矢印・Ctrl+Shift+M）**：**A. 消す（選んだ）** / B. 残す。あわせて、矢印を使う Cmd+Option+矢印（隣のペインへ移る）も消した（方針 4）。
8. **文字を選んでコピー・画面の URL を開く（今はマウスだけ）**：**A. マウスを主にする（選んだ）** / B. コピーモードと URL のヒントモードを別の Issue で作る。範囲や 1 か所を指す操作は、マウスの方が速く正確なため。
9. **Linux の「隣のペインへ移る」（Ctrl+Shift+矢印は shj の単語選択を奪っている）**：A. 今のまま / **B. リーダー `h` `j` `k` `l` だけにする（選んだ）** / C. 別のキーに替える。ペインを移るのは一番よく使う操作なので、リーダーの 1 段目に置き、続けて押せるようにした。
