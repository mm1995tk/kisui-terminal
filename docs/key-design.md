# kisui-terminal の新しいキー操作（案）

キー操作を作り直す案。今のキーとマウスの操作の一覧は [`keys.md`](keys.md)。この文書は案であり、PR で承認されたあとに実装する（実装は別の Issue と PR。この PR ではコードを変えない）。承認されたら、この文書が「決まったキーの表」になり、「案」の語を外す。

- 「Mac」は macOS、「Linux」は Linux と Windows（Mac 以外）。Cmd は Mac の ⌘、Super は Linux の Super（Windows キー）、Option は Mac の ⌥。
- 迷う所は 8 章に候補を並べた（PR の説明の最初にも同じ一覧がある）。表の中の「選択 n」は、8 章のその番号を指す。表には、各選択の先頭の案を置いてある。
- 内蔵ブラウザの欄だけのキー（ブラウザの欄の ← → ↻・アドレス欄・↗・×）は、この表に入れない。内蔵ブラウザの欄は #96（PR #105）で消える前提で、#105 より前にこの表が承認されても、その欄のキーは足さない。

## 1. 方針

1. キー操作が主で、マウスは逃げ道。すべての操作にキー操作を用意する。ホームポジションから手を離させない。
2. GUI の方が優れている操作（スクロール・OS からのドロップ・文字をドラッグで選ぶ）は、GUI を主にしてよい。そのときは、理由を表に書く（5 章）。
3. 操作は 3 つの層で持つ。
   - **リーダー**：Mac は Cmd+K、Linux は Super+K。場所のキー（下の層）とアプリの外のキー（Option+Space）を除く、すべての操作がここの下にある。押すと、次に押せるキーと動きが出る（which-key の形）。`?` で全部のキーの一覧が出る。覚えなくても使える層。
   - **近道**：よく使う操作だけ、リーダーを通さずに 1 回で押せるキーを残す。リーダーの下にも同じ操作がある（近道を忘れても困らない）。
   - **場所のキー**：ファイルツリー・CHANGES・動画・画像・リサイズモードの中で、その欄にフォーカスがあるときだけ効くキー（修飾キー無し）。リーダーの木には載せず、その欄の `?` の一覧に載せる。ターミナルの欄にフォーカスがあるときは効かないので、シェルや shj のキーを奪わない。
4. kisui-terminal が奪うキーは、できるだけ少なくする。ターミナルの中のプログラム（シェル・vim・shj・herdr など）に届くべきキーは奪わない。奪うのは、Mac の Cmd 系（ターミナルのプログラムは受けない）と、Linux の Super 系・Ctrl+Shift 系（旧来の端末の符号では Ctrl+Shift+字が Ctrl+字と同じで、区別して受けるプログラムはほぼ無い。ただし矢印は別で、Ctrl+Shift+矢印は旧来の端末でも Ctrl+矢印と別の符号になり、shj が単語選択に使う。7.1）に限る。Linux の Ctrl 単独・Alt 単独のキーは、新しく奪わない（7 章）。
5. 近道は 1 つの操作に OS ごとに 1 つ。別名で同じ操作を二重に持たない。

## 2. リーダー

### 2.1 入るキーと動き

| OS    | キー（案）                     | 注意                                                                                                                               |
| ----- | ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| Mac   | Cmd+K                          | Mac の OS・WebView・ターミナルのプログラムは Cmd+K を受けない。                                                                    |
| Linux | Super+K（選択 1 で変わりうる） | ウィンドウマネージャーが先に取る環境では届かない（7.3）。Windows では Win+K が OS の「キャスト」に使われていて、アプリに届かない。 |

動き：

- 押すと、画面の隅に次に押せるキーとその動きの一覧を出す。キーが向く先は、押した瞬間にフォーカスがあった欄のまま変わらない。
- 次のキーで、動きを行う（葉）か、一段下の一覧に入る（グループ）。キーは、1 つの一覧の中で重ならない。
- `Esc` はリーダーを出る。`Backspace` は一段戻る（一番上では出る）。リーダーのキーをもう 1 度押しても出る。
- 一覧に無いキーを押したら、そのキーは捨てて（シェルや shj には送らない）、リーダーを出る。誤って文字がシェルに入るのを避けるため。
- 時間で閉じない（押し直しを強いない。shj の Space の案内と同じ）。
- 入るときの条件：かな漢字変換中（`isComposing`）は受けない。窓（ダイアログ）が出ている間は受けない（窓の `Esc` が先）。それ以外はどこにフォーカスがあっても効く（ファイルツリー・CHANGES・動画・画像の中でも）。リサイズモードの中では、リーダーに入らず、リサイズモードのキーを優先する。
- 案内の表と、実際に受けるキーは、1 つの定義から作る（ずれないようにする。#92 で実装）。

### 2.3 場所のキーでも `?`

ファイルツリー・CHANGES・動画・画像の欄にフォーカスがあるとき、`?` でその欄のキーの一覧を出す（ツリーと CHANGES には、今 `?` の割り当てが無い）。リサイズモードは、入っている間、使えるキーを画面に出す（#92）。

## 4. 場所のキー（その欄にフォーカスがあるときだけ）

今のキーは残す。リーダーには重ねない（場所のキーはその欄の中で、リーダーは欄の外から呼ぶ）。足すのは次のとおり。

| 場所                    | キー                   | 動き                                              | 決め        | 理由                                                                              |
| ----------------------- | ---------------------- | ------------------------------------------------- | ----------- | --------------------------------------------------------------------------------- |
| ファイルツリー・CHANGES | `?`                    | その欄のキーの一覧を出す                          | 足す        | 2.3。                                                                             |
| ファイルツリー          | `m`                    | 「ここへ移動」（フォルダの行だけ）                | 足す        | 今は右クリックのメニューにしか無い。mv の `m`。                                   |
| ファイルツリー          | `c`                    | 名前をコピー                                      | 足す        | 同上。`y`（相対パス）・`Y`（絶対パス）と並ぶ「コピー」。                          |
| ファイルツリー          | `.`（または Menu キー） | 右クリックのメニューを、選んでいる行で開く        | 足す        | 将来メニューに項目が増えても、キーで届く逃げ道になる。                            |
| 画像の欄                | `+` `=` / `-` / `0`    | 拡大・縮小・元の大きさ                            | 足す（#93） | 動画の欄と同じ形。全体の倍率（Cmd+=・Ctrl+=）は修飾キー付きなので重ならない。    |
| 画像の欄                | `h` `j` `k` `l` / 矢印 | 拡大中に、見える場所を動かす                      | 足す（#93） | 同上。                                                                            |
| 画像の欄                | `Esc`                  | ターミナルへ戻る                                  | 足す        | ツリー・CHANGES と同じ。                                                          |

残すもの：ファイルツリー・CHANGES の移動と操作（`keys.md` の 1.4）、動画の欄（1.5）、リサイズモード（1.3）、窓・メニューの中（1.6。`Esc` は取り消し、`Enter` は決める）。

**窓・お知らせの決まり**：窓（ダイアログ）は `Enter` が主のボタン、`Esc` が取り消し。ボタンが 3 つ以上のときは、ボタンに押す字を付ける。右下のお知らせと「新しい版があります」は、リーダー `n` の下から操作する（2.2）。

**同じ字が別の意味になる件**：ツリー・CHANGES・リサイズモードの `h` `j` `k` `l` は移動、動画の欄は `j` `l` が 10 秒の移動、`k` が再生・停止（YouTube と同じ。動画を見るための決まりなので、GUI の方を主にして変えない）。ツリーの `r` は名前の変更、CHANGES の `r` は読み直し。これは、場所ごとに案内を出す（`?`）ことで補い、字は変えない。

### 5.2 マウスでしかできなかった操作（`keys.md` の 2 章）

| `keys.md` | 操作                                                              | 新しいキー、または GUI を主にする理由                                                                                                                                              |
| --------- | ----------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 2.1       | 文字をドラッグで選んでコピー                                      | **GUI 主**。キーだけで選ぶには、端末の中を動くコピーモードが要り、大きい機能になる。選択 8 に候補を置いた。シェルや shj は、自分のキー（shj の `Space y` など）でコピーできる。   |

## 7. shj・ターミナルの中のプログラムのキーを奪わないか

kisui-terminal は、キーを欄に届く前（`window` の `keydown` の capture）で受ける。GUI のキーに当たったキーは、シェルにも shj にも送らない。そこで、新しい表のキーが、shj（[shijimi-editor の README](https://github.com/mm1995tk/shijimi-editor) の「Keys」の章）と、ターミナルの中の一般のプログラムのキーと重ならないかを調べた。

### 7.1 shj のキーとの照合

shj が受けるキー（README の Space メニュー・Helix モード・VS Code モード・ターミナル欄・検索パネル）：`Space` で始まる操作（`Space f/b/w/e/k/o/r/s/d/g/G/m/v/y/p/?` など）、`F1`、`Ctrl+K`、`Ctrl+P`、`Ctrl+B`、`Ctrl+E`、`Ctrl+G`、``Ctrl+` ``、`Ctrl+J`、`Ctrl+S`、`Ctrl+W`、`Ctrl+Tab`、`Ctrl+\`、`Ctrl+1` / `Ctrl+2`、`Ctrl+Q`、`Alt+R`、`Alt+A`、`Alt+I`、`Alt+C`、`Alt+←` `Alt+→`、`Ctrl+Alt+D` / `Ctrl+Alt+U`、`Ctrl+O` / `Ctrl+I`、`Ctrl+C`、`Ctrl+X`、`Ctrl+Z`、`Ctrl+F`、`Ctrl+Shift+←` `Ctrl+Shift+→` `Ctrl+Shift+Home` `Ctrl+Shift+End`（選択）、`Ctrl+Shift+Z`（やり直し）、`Ctrl+_` / `Ctrl+/`（コメントの切り替え）ほか。shj は Cmd・Super を使わない。

| 新しいキー                                                                                                       | shj のキーとの関係                                                                                                                                                                                   | 結論                        |
| ---------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------- |
| リーダー Cmd+K（Mac）・Super+K（Linux）                                                                          | shj の `Ctrl+K`（コマンドパレット）とは別のキー。Cmd・Super は shj に届くキーではないので、shj のキーが減らない。リーダーの中の `w` `m` `p` などは、リーダーが受けるので shj には届かない。shj の `Space` のメニューとは入り口が別で、リーダーは `Space` を使わない。 | 奪わない                    |

場所のキー（修飾キー無しの `m` `c` `.` `?`・画像の `+` `-` `0`）は、ファイルツリー・CHANGES・画像の欄にフォーカスがあるときだけ効く。そのときのフォーカスは kisui-terminal の欄にあり、shj のキーを受ける端末の欄にはないので、shj には影響しない。ただし CHANGES は、`s` `r` `R` `:` `Space` を shj に渡す（`keys.md` の 1.4）。ここに足す `?` は、今 CHANGES から shj に渡している字に無いので、kisui-terminal が受けても shj のキーは減らない。

### 7.3 Linux のリーダー Super+K が届かない環境

Linux には、Super のキーをウィンドウマネージャー・デスクトップが先に取る環境がある。

- i3・sway・Hyprland など：Super+K を「上のウィンドウへフォーカス」などに割り当てている設定が多い（vim 風の設定）。設定を変えない限り届かない。
- Windows：Win+K は OS の「キャスト」で、アプリに届かない。
- Wayland：コンポジターが取るキーは、アプリに届かない。
- GNOME・KDE の既定では、Super+K に割り当ては無い（Super 単独で押して離すと、概要やメニューが開く）。

届かない環境では、リーダーに入れない。選択 1 の B か C（Ctrl+Shift+K）を選ぶと、そうした環境でも入れる。Mac の Cmd+K は、OS・WebView が取らない。

選択 4 の A の Ctrl+Super+h/j/k/l（Linux の近道）も、同じ環境（i3・sway・Hyprland の vim 風の設定、Wayland のコンポジター）に取られうる。選択 1 で C（Super を使わない）を選ぶなら、選択 4 の Linux の近道も Super を使わない形（B か C）にする必要がある。

## 8. 選んでほしいこと

PR の説明の最初にある一覧と同じ。表には、各選択の先頭の案（A）を置いた。

1. **Linux・Windows のリーダーのキー**
   - A. Super+K だけ（Issue のとおり。i3・sway・Windows では届かない）
   - B. Super+K と Ctrl+Shift+K の両方で入れる（Super が届かない環境でも使える。Ctrl+Shift の近道と同じ系統）
   - C. Ctrl+Shift+K だけ（Super は一切使わない。#88 の Ctrl+Super+h/j/k/l の近道は、選択 4 で別のキーにする）
2. **Linux の表示を小さくするキー（Ctrl+`-`）は readline の undo を奪う**
   - A. 今のまま（ブラウザと同じ習慣を優先。シェルの undo と shj のコメントの切り替え（`Ctrl+_`）が、この 2 つのプログラムに届かない。shj は Ctrl+`/` でも切り替えられる）
   - B. Linux の表示の大きさは、リーダー `v + - 0` だけにする（Ctrl+`=` `0` も近道から外す。シェルの undo と shj のコメントの切り替えが届く）
3. **Linux のワークスペースを番号で選ぶ近道（Mac は Cmd+1〜9）**
   - A. 置かない（リーダー `w 1`〜`w 9` と、Ctrl+Super+j/k の順送り）
   - B. Ctrl+Alt+1〜9（デスクトップの設定で別の割り当てがあることがある）
   - C. Alt+1〜9（readline の数引数・shj の検索パネルの `Alt+1` と重なる。奪う）
4. **ワークスペースとマシンを移る近道**
   - A. #88 の案のまま（Mac は Ctrl+Cmd+j/k が次・前のワークスペース、h/l が前・次のマシン。Linux は Ctrl+Super）
   - B. ワークスペースは Mac の Cmd+Shift+] / [ と Linux の Ctrl+PageDown / PageUp（macOS の Terminal.app・Safari と GNOME Terminal の「次のタブ」の習慣。shj は使っていないが、vim などが使いうるキーを奪う）、マシンは A のまま
   - C. 近道は置かず、リーダー `w j/k` `m h/l` だけにする
5. **ワークスペースを作る近道**
   - A. 置かない（リーダー `w n` だけ）
   - B. Cmd+T（Mac）・Ctrl+Shift+T（Linux）（新しいタブの習慣）
6. **Linux の「分けた欄を閉じる」近道（今は Mac の Cmd+W だけ）**
   - A. Ctrl+Shift+W を足す
   - B. 足さない（リーダー `p x` だけ）
7. **Mac の別名（Ctrl+Shift+矢印・Ctrl+Shift+M）**
   - A. 消す（Cmd+Option+矢印・Cmd+Shift+Enter だけ。shj の単語選択（Ctrl+Shift+←/→）など、端末の中のプログラムが使うキーを奪わなくなる）
   - B. 残す（今の動きを変えない）
8. **キーだけでできない 2 つの操作（文字を選んでコピー、画面の URL を開く）**
   - A. GUI を主にする（今のまま。5.2 の理由）
   - B. キーでもできるようにする。コピーモード（端末の中をキーで動いて選ぶ）と、URL の hint mode（画面の URL に字を振って選ぶ）を、別の Issue で作る
9. **Linux の「隣の欄へ移る」（今は Ctrl+Shift+矢印。shj の単語選択を奪っている）**
   - A. 今のまま（今の動きを変えない。shj の Ctrl+Shift+←/→ は届かない）
   - B. 近道を置かず、リーダー `p h/j/k/l` だけにする（shj のキーを奪わなくなる）
