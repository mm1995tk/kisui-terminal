# kisui-terminal のキー操作

kisui-terminal のキー操作の表。今のキーとマウスの操作の一覧は [`keys.md`](keys.md)。この表は #91 で決めたもの。リーダー・案内（`?`）・近道の入れ替えは #92 で実装した（コマンドの表は `app/src/commands.ts`）。場所のキー（5 章）は #115 で入れた（定義は `app/src/placeKeys.ts`。判定は場所ごとに `tree/keys.ts`・`changes/keys.ts`・`terminal/media.ts`・`terminal/imageView.ts`）。キーを足す・変えるときは、この表も直す。

- 「Mac」は macOS、「Linux」は Linux と Windows（Mac 以外）。Cmd は Mac の ⌘、Option は Mac の ⌥。
- 9 章に、決めるときに比べた候補と、選んだ案を残した。
- 内蔵ブラウザのペインだけのキー（ブラウザのペインの ← → ↻・アドレス欄・↗・×）は、この表に入れない。内蔵ブラウザのペインは #96（PR #105）で消える前提。

## 1. 用語

画面の部分の呼び名。会話と文書は和名、コンポーネントの名前は英名を使う（コンポーネントのドキュメンテーションコメントには和名を書く）。今のコードの名前とは違うものがある。名前をそろえるのは別の作業。

## 2. 方針

1. **キー操作が主で、マウスは逃げ道。** すべての操作にキー操作を用意する。ただし、マウスの方が優れている操作は、マウスを主にしてよい。そのときは理由を表に書く（6.2）。
2. **shj と役割を分ける。** shj の `Space` は、エディタとその周り（ファイルツリー・変更一覧・分割・プレビュー）の操作を受け持つ。kisui のリーダーは、kisui にしかない操作（ワークスペース・マシン・ペイン・サイドバーの開け閉め・表示の大きさ・お知らせ・クリップボードの履歴）だけを受け持つ。同じ操作を両方に持たない。ファイルツリーと変更一覧はプライマリのペインの shj があるときだけ出るので、そこへ移るのは shj の `Space e` `Space g` に任せる。
3. **shj のキーを奪わない。** kisui が受けるのは、Mac は Cmd を含むキー、Linux は Ctrl+Shift+字だけ。Linux では Super・Ctrl 単独・Alt 単独のキーを新しく使わない。例外は、何も奪わない今の Ctrl+`=` `0`（4.2）、アプリの外のキー（Option+Space / Alt+Space）、ダイアログが出ている間だけ効く Ctrl+J / Ctrl+K（5 章）。旧来の端末の符号では Ctrl+Shift+字は Ctrl+字と同じで、kisui は Shift 付きだけを取るので、Ctrl+字は shj やシェルに届く。矢印は別で、Ctrl+Shift+矢印は Ctrl+矢印と別の符号になり shj が使うので、取らない（8 章）。
4. **ホームポジションから手を離させない。** 新しいキーに矢印・PageUp・PageDown を使わない。向きと順送りは vim の流儀の `h` `j` `k` `l`（`j` が次・下、`k` が前・上、`h` `l` が左右や一段大きい単位の前後）、直前の場所との行き来は `Tab`。Emacs の流儀（Ctrl+N・Ctrl+P）は混ぜない。今ある矢印のキー（ダイアログ・動画）は、`h` `j` `k` `l` と並べて残す。
5. **リーダーを入り口にする。** 操作は次の層で持つ。
   - **リーダー**：Mac は Cmd+K、Linux は Ctrl+Shift+K。押すと、次に押せるキーの一覧（リーダーの一覧）が出る。場所のキーとアプリの外のキー（Option+Space）を除く、すべての操作がここの下にある。覚えなくても使える層。
   - **グループの入口の近道**：リーダーのグループに 1 回で入るキー。字はリーダーの中と同じで、Mac は Cmd+Shift、Linux は Ctrl+Shift を付ける（4.1）。
   - **近道**：今あって何も奪わない近道だけを残す。新しい近道はほとんど足さない（4.2）。リーダーの下にも同じ操作がある。
   - **場所のキー**：ファイルツリー・変更一覧・動画・画像・リサイズモード・ダイアログの中で、そこにフォーカスがあるときだけ効くキー。リーダーには載せず、その場所の `?` の一覧に載せる。
6. **近道は 1 つの操作に OS ごとに 1 つ。** 別名で同じ操作を二重に持たない。Mac の Cmd（と Cmd+Shift）のキーは、Linux では Ctrl+Shift のキーにする。Mac で Cmd+Shift を使うキーも、Linux では Ctrl+Shift（Shift を二重にはしない）。
7. **リーダーの一覧の葉は、名前の付いたコマンドを呼ぶ。** キーとリーダーの一覧は、コマンドの表（コマンドの名前・キー・説明）という 1 つの定義から作る。案内とずれないようにし、キーを変えるときも 1 か所を直せば済むようにするため（#92 で実装）。`kisui` のコマンドから呼べるようにすることは、今はしない。

## 3. リーダー

### 3.1 入るキーと動き

| OS    | キー         | 注意                                                                                                                                                        |
| ----- | ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Mac   | Cmd+K        | Mac の OS・WebView・ターミナルのプログラムは Cmd+K を受けない。                                                                                             |
| Linux | Ctrl+Shift+K | Shift なしの Ctrl+K は、shj（コマンドパレット）とシェルに届く。Super+K と違い、Windows（Win+K は OS のキャスト）や i3・sway でもウィンドウマネージャーに取られない。 |

動き：

- 押すと、画面の隅にリーダーの一覧を出す。キーが向く先は、押した瞬間にフォーカスがあったペインのまま変わらない。
- 次のキーで、動きを行う（葉）か、一段下の一覧に入る（グループ）。キーは、1 つの一覧の中で重ならない。
- `Esc` はリーダーを出る。`Backspace` は一段戻る（一番上では出る）。リーダーのキーをもう 1 度押しても出る。
- 一覧に無いキーを押したら、そのキーは捨てて（シェルや shj には送らない）、リーダーを出る。誤って文字がシェルに入るのを避けるため。
- **続けて押せる葉**：3.2 の表で「続けて」と書いた葉は、行ったあともリーダーを出ず、同じ一覧のまま次のキーを待つ。ペインを `j` `j` `l` と続けて移れる。ほかのキーを押すと、上の決まりどおり、そのキーを捨てて出る。
- 時間で閉じない（押し直しを強いない。shj の Space の案内と同じ）。
- 入るときの条件：かな漢字変換中（`isComposing`）は受けない。ダイアログが出ている間は受けない（ダイアログの `Esc` が先）。それ以外はどこにフォーカスがあっても効く（ファイルツリー・変更一覧・動画・画像の中でも）。リサイズモードの中では、リーダーに入らず、リサイズモードのキーを優先する。
- リーダーの一覧と、実際に受けるキーは、コマンドの表から作る（2 章の方針 7。#92 で実装）。

### 3.3 場所のキーでも `?`

ファイルツリー・変更一覧・動画・画像のペインにフォーカスがあるとき、`?` でその場所のキーの一覧を出す。リーダーの `?`（全部のキーの一覧）も、今フォーカスがある場所があれば、その場所のキーを先に出す（#115）。リサイズモードは、入っている間、使えるキーを画面に出す（#92）。

## 4. 近道（リーダーを通さずに 1 回で押せるキー）

### 4.1 グループの入口の近道（新しく足す）

| 入る先                         | Mac         | Linux        | 理由                                                                                                                             |
| ------------------------------ | ----------- | ------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| リーダー → `w`（ワークスペース） | Cmd+Shift+W | Ctrl+Shift+W | ワークスペースとマシンを移るのに、リーダーを含めて 3 回押さずに済む。字はリーダーの中と同じ `w`。                                |
| リーダー → `p`（ペイン）         | Cmd+Shift+P | Ctrl+Shift+P | 分ける・閉じる・隠す・大きさを変えるに 1 回で入れる。                                                                            |

表示の大きさのグループ（`v`）には作らない。Linux の Ctrl+Shift+V は、ターミナルの貼り付けとして広く使われているため。Cmd+M（Mac がウィンドウをしまうキー）のように、OS が使うキーは入口にしない。

### 4.2 今の近道をどうするか

今のキー（`keys.md` の 1.1・1.2 にあるもの）を、「残す」「消す」で 1 つずつ決めた。

| 操作                                | 今の Mac                                | 今の Linux      | これから（Mac）  | これから（Linux） | 理由                                                                                                                                                                 |
| ----------------------------------- | --------------------------------------- | --------------- | ---------------- | ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| リーダー                            | （無い）                                | （無い）        | Cmd+K            | Ctrl+Shift+K      | 全操作の入り口（3.1）。                                                                                                                                              |
| 表示を大きくする                    | Cmd+`+` / Cmd+`=`                       | Ctrl+`+` / `=`  | 残す             | 残す              | ブラウザ・エディタと同じ習慣で、何も奪わない。リーダー `v +`。                                                                                                       |
| 表示を小さくする                    | Cmd+`-`                                 | Ctrl+`-`        | 残す             | **消す**          | Linux の Ctrl+`-` は端末の `C-_` と同じ符号で、shj のコメントの切り替え（`Ctrl+_`）とシェルの undo を奪っていた。リーダー `v -`。                                     |
| 表示を元に戻す                      | Cmd+`0`                                 | Ctrl+`0`        | 残す             | 残す              | 何も奪わない。リーダー `v 0`。                                                                                                                                       |
| ペインを隠す・戻す                  | Cmd+Shift+Enter、または Ctrl+Shift+M    | Ctrl+Shift+M    | Cmd+Shift+Enter  | 残す              | Mac の別名 Ctrl+Shift+M を消す（方針 6）。リーダー `p z`。                                                                                                           |
| クリップボードの履歴                | Cmd+Shift+H                             | Ctrl+Shift+H    | 残す             | 残す              | 何度も使う。リーダー `y`。                                                                                                                                           |

## 8. shj・ターミナルの中のプログラムのキーを奪わないか

kisui-terminal は、キーをペインに届く前（`window` の `keydown` の capture）で受ける。GUI のキーに当たったキーは、シェルにも shj にも送らない。そこで、この表のキーが、shj（[shijimi-editor の README](https://github.com/mm1995tk/shijimi-editor) の「Keys」の章）と、ターミナルの中の一般のプログラムのキーと重ならないかを調べた。

### 8.1 shj のキーとの照合

shj が受けるキー（README の Space メニュー・Helix モード・VS Code モード・ターミナルパネル・検索パネル）：`Space` で始まる操作（`Space f/b/w/e/k/o/r/s/d/g/G/m/v/y/p/?` など）、`F1`、`Ctrl+K`、`Ctrl+P`、`Ctrl+B`、`Ctrl+E`、`Ctrl+G`、``Ctrl+` ``、`Ctrl+J`、`Ctrl+S`、`Ctrl+W`、`Ctrl+Tab`、`Ctrl+\`、`Ctrl+1` / `Ctrl+2`、`Ctrl+Q`、`Alt+R`、`Alt+A`、`Alt+I`、`Alt+C`、`Alt+←` `Alt+→`、`Ctrl+Alt+D` / `Ctrl+Alt+U`、`Ctrl+O` / `Ctrl+I`、`Ctrl+C`、`Ctrl+X`、`Ctrl+Z`、`Ctrl+F`、`Ctrl+Shift+←` `Ctrl+Shift+→` `Ctrl+Shift+Home` `Ctrl+Shift+End`（選択）、`Ctrl+Shift+Z`（やり直し）、`Ctrl+_` / `Ctrl+/`（コメントの切り替え）ほか。shj は Cmd・Super を使わない。

| kisui のキー                                                                                       | shj のキーとの関係                                                                                                                                                                                       | 結論     |
| -------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |

## 9. 決めるときに比べた候補と、選んだ案

PR #106 で、次の 9 つを比べて選んだ。決めるときに先に置いた原則は 2 章（shj と役割を分ける・shj のキーを奪わない・矢印を使わない・リーダーを入り口にして近道は最小）。

1. **Linux・Windows のリーダーのキー**：A. Super+K だけ / B. Super+K と Ctrl+Shift+K の両方 / **C. Ctrl+Shift+K だけ（選んだ）**。Super+K は Windows と i3・sway で届かない。Linux の kisui のキーをすべて Ctrl+Shift+字にそろえられる。
2. **Linux の表示を小さくするキー Ctrl+`-`（shj のコメントの切り替えとシェルの undo を奪う）**：A. 今のまま / **B. リーダー `v` だけにする（選んだ）**。ただし、何も奪わない Ctrl+`=` と Ctrl+`0` は近道として残す。
3. **Linux のワークスペースを番号で選ぶ近道**：**A. 置かない（選んだ。リーダー `w 1`〜`w 9`）** / B. Ctrl+Alt+1〜9 / C. Alt+1〜9。
4. **ワークスペースとマシンを移る近道**：A. #88 の案（Ctrl+Cmd / Ctrl+Super + h/j/k/l） / B. Cmd+Shift+] / [・Ctrl+PageDown / PageUp / **C. 近道なし、リーダーだけ（選んだ）**。使う回数が多くないため。代わりに、ワークスペースのグループに 1 回で入る近道（Cmd+Shift+W / Ctrl+Shift+W）を足した。B は PageUp・PageDown を使うので、方針 4 にも合わない。
5. **ワークスペースを作る近道**：**A. 置かない（選んだ）** / B. Cmd+T・Ctrl+Shift+T。
6. **Linux の「分けたペインを閉じる」近道**：A. Ctrl+Shift+W を足す / **B. リーダーだけ（選んだ）**。Ctrl+Shift+W は、ワークスペースのグループの入口に使う。
